# 南枫知识库文档同步

## 先分类再写入

- `AGENTS.md`：长期工作边界、数据安全和交付规则。
- `docs/CURRENT_HANDOFF.md`：当前分支、动态进度、运行结果、下一步和阻塞。
- 架构/领域文档：稳定设计、对象关系、业务契约与明确例外。
- 发布文档：标签、安装包、SHA-256、签名与远端复验。
- 开发档案：带日期的历史复盘，不替代当前交接。

## 取证与冲突处理

1. 为每项结论记录代码路径、测试/运行命令、Git commit 或文档章节；不要凭空补齐产品动机或验收结论。
2. 冲突时以当前代码和最新可重复验证为准，在“冲突记录”中写出旧说法、当前证据、影响和处理方式。
3. 历史文档可保留历史事实，但不得被写成“当前状态”；动态数据只保留一个权威入口。
4. 不因同步文档而改业务逻辑、迁移、正式数据或发布资产，除非用户明确扩大范围。

## 完成检查

- Markdown 标题层级、链接、路径、命令和版本号可读且一致。
- 明确标识验证层级与证据日期，分开“已确认”“合理推测”“未确认”。
- 列出改动文件、未确认问题和建议的下一步，不承诺未经执行的发布或真实业务结果。
