# Formal distillation SOP

## Purpose

Turn a completed or stable milestone into evidence-backed rules without rewriting history, leaking sensitive data, or treating unverified observations as facts.

## Procedure

1. Fix the evidence boundary: code revision, documents, test output, release record and evidence date.
2. Separate facts, inferences, open questions and recommendations.
3. Map each feedback item to root cause, decision, implementation, verification and reusable rule.
4. Classify every conclusion as generic, project-specific or not directly reusable.
5. Register conflicts explicitly; current code and repeatable verification take precedence over stale prose.
6. Publish a concise archive, durable rules and a dynamic handoff update only where each belongs.

## Release gate

Do not call a distillation complete if it contains unfinished markers, secrets, absolute personal paths, unsupported claims, broken links or empty headings.
