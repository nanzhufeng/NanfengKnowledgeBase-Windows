# 南枫知识库排错

## 先建立事实

1. 记录用户可见现象、发生时间、输入范围、环境、版本和可复现步骤。
2. 只读检查 `git status`、应用/服务日志、数据库完整性、进程与端口状态；不先重启、清库、迁移或停止占用进程。
3. 区分 Browser、Tauri WebView、Rust command、SQLite、外部 AI 供应商和真实数据层，避免跨层猜测。

## 收敛方法

- 优先级：当前代码与可重复证据 > 当前交接记录 > 历史文档。
- 沿调用链定位：界面事件 → TypeScript service/Zod 校验 → Tauri command → Rust repository → SQLite/外部服务。
- 每次只验证一个可证伪假设；保留输入与输出的最小脱敏样本。
- 两次修复未消除同一症状时，停止叠加补丁，回到复现、事实、假设与根因，检查契约、迁移和环境差异。

## 专项检查

- 导入：文件格式、编码、归档索引、重复判定、事务、附件路径与取消语义。
- 数据库：schema 版本、migration 顺序、外键、WAL、完整性检查和备份可恢复性。
- AI/缓存：冻结路由、供应商返回、重试、缓存键版本与命中/回退记录；绝不输出密钥或原始敏感正文。
- E2E：先查端口占用，不能为运行测试擅自终止用户服务。

## 结论格式

给出“已证实根因、排除的假设、最小修复、回归验证、仍未验证边界”。修复未获授权时只给诊断和方案，不改业务代码。
