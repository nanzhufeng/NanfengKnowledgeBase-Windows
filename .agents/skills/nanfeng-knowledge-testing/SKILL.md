# 南枫知识库测试与验收

## 选择验证层级

| 改动类型 | 最低验证 |
| --- | --- |
| TypeScript/React 行为 | 定向 Vitest + `npm.cmd run typecheck` |
| Rust repository、migration、command | 定向 Cargo 测试；必要时全量 `cargo test` |
| 浏览器交互 | 先检查端口，再执行 Playwright；说明是否复用真实服务 |
| 打包或安装 | 仅在目标包含发布时构建，记录安装包、SHA-256 与实际安装验证 |
| AI 或缓存策略 | 定向契约测试 + 脱敏小批真实链路；单独报告质量范围和费用数据缺口 |

## 执行规则

1. 先读取脚本、测试配置与当前端口状态，确认命令不会覆盖用户服务或正式数据。
2. 使用项目既有共享构建缓存；Cargo 或打包命令可能产生缓存，执行后如实记录，不擅自清理。
3. 失败时保留原始错误和最小复现；不要为了绿灯而跳过、弱化断言或改配置复用未知服务。
4. 用实际输出核对测试数量，避免以旧文档中的计数替代当前结果。

## 验收报告

逐项标注：已实现、定向测试、全量测试、类型检查、构建、隔离应用路径、真实业务路径、正式发布。每一项写命令、结果、证据日期和未覆盖边界。
