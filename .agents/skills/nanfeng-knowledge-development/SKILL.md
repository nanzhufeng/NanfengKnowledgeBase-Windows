# 南枫知识库开发

## 开工取证

1. 阅读根目录 `AGENTS.md`、`docs/CURRENT_HANDOFF.md` 和与目标有关的领域文档。
2. 检查 `git status --short`，保护既有未提交成果；确认实际仓库、分支与目标范围。
3. 用当前代码定位职责，而不是依据旧设计稿推断。记录入口、持久化、IPC、服务层、界面和测试的所有者。

## 按链路实现

- 数据对象变更：先设计新 migration，再更新 Rust repository、Tauri command、TypeScript service、界面和测试；不可改写已发布 migration。
- UI 变更：遵循当前设计基线与现有皮肤 token，不改变已锁定的信息架构、组件职责或可访问操作。
- AI 变更：在创建任务时冻结模型路由；保留来源、任务、应用、撤销和失败记录。密钥绝不进入 SQLite、日志或前端。
- Prompt Cache 变更：使用版本化稳定摘要隔离任务阶段、模型和提示词；不得以原始正文或密钥作为缓存材料。

## 安全边界

- 正式数据迁移仅能在预检、备份和完整性验证完成后执行，且须有用户授权。
- 不删除构建缓存、验收程序或用户数据；先输出 Preview、精确路径、体积、排除项和可回滚方式。
- 不把模拟数据、编译成功或小批样本表述为真实业务全量结论。

## 最小验证与交接

1. 先运行受改动影响的单元/集成测试，再运行类型检查；仅在需要时做构建或真实路径验收。
2. 报告验证层级、命令、结果、未覆盖项和风险。
3. 将动态状态写入 `docs/CURRENT_HANDOFF.md`，将长期规则写入对应领域文档；不要把临时数字塞入 `AGENTS.md`。
