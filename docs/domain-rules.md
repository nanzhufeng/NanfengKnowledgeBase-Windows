# 知识领域规则

本文只记录南枫知识库独有且稳定的业务规则。最高产品边界仍以 `南枫知识库_产品定义与自动分类主规格.md` 为准。

## 对象职责

### Domain

- 表示长期稳定的顶层知识领域。
- Domain 不能直接持有原始正文；来源和笔记通过 Topic 进入领域。

### Topic / Subtopic

- Topic 是长期知识结构的第一层对象。
- Subtopic 不使用独立对象或表，与 Topic 共用模型，通过 `parentTopicId` 形成层级。
- 每个 Topic 只有一个主父级和一个主领域，保证导航与分类路径唯一。
- 其他父级、相关主题、因果、对比等联系必须使用 TopicRelation，不得复制 Topic。
- 主题名称可以修改；旧名称应转为别名或重定向，不能导致来源失联。

### Source Item

- Source Item 表示不可替代的原始资料。
- 原始文件、原始文本、原始 JSON、哈希、来源日期和来源平台属于保真字段。
- 提取、分类、合并、拆分和模型辅助不得覆盖原始资料。
- 新来源在完成提取和标准化后进入收录箱，再生成分类建议。

### Note

- Note 是用户提炼后的可编辑内容，与 Source Item 分离。
- Note 可以引用多个来源，但来源仍保持独立身份。
- Note 只有一个主要主题，可通过关系表连接其他主题。

### Judgment Snapshot

- 判断使用追加快照，不覆盖历史判断。
- 每个快照必须有判断日期、置信度、变化原因和当时未解决问题。
- Turning Point 只引用真正改变判断的快照变化；普通更新时间不是转折。

### Evidence

- Evidence 必须关联 Source Item。
- 精确锚点按来源类型记录页码、时间码、消息 ID 或短文本引用；没有锚点时必须明确为空，不能伪造。
- 支持、反对和背景证据分开；可信度、验证状态和有效状态不能混成一个字段。

### Open Question

- 待验证问题必须关联 Topic。
- “是否影响当前判断”与重要程度分开。
- 问题解决时保存解决说明和时间，不直接删除。

## 分类建议规则

唯一规则所有者：`src/knowledge/deterministicClassifier.ts`。

唯一公开入口：

```ts
classifySource(context: ClassificationContext): ClassificationResult
```

输入适配器只提供：

- 标准化来源；AI 会话必须投影为当前分支的用户可见正文，不得把保真的原始 JSON、模型名、搜索元数据、附件指针或隐藏思考作为分类文本；
- 标题和可见正文组成同一内容证据入口；`keyword`、`entity`、排除词等内容规则必须同时检查标题与正文，不能要求标题中的明确主题短语在长正文里重复出现；
- 主题候选；
- 显式规则；
- 历史确认数据；
- 可选的本地 FTS5/BM25 归一化分数。

输入适配器、页面和持久化层不得自行裁决最终主题。

### 固定信号

| 信号 | 权重 | 所有权 |
|---|---:|---|
| 显式规则 | 35 | 分类器匹配用户规则、路径、来源、标签和字段 |
| 别名与实体 | 25 | 分类器匹配主题名称、别名和本地实体词典 |
| 全文相关 | 20 | SQLite 适配器提供 FTS5/BM25 归一化分数；无适配器时只用于原型的本地词项相似度 |
| 集合相似 | 10 | 分类器计算关键词集合相似度 |
| 时间历史 | 10 | 分类器使用近期主题、历史确认和同批资料 |

五项权重总和必须为 100。分类结果必须记录算法版本和每项贡献分。

### 固定阈值

| 置信度 | 结果 |
|---|---|
| `≥90` | `auto_eligible`：具备自动接受资格，但实际写入必须经统一用例并记录可撤销操作 |
| `70–89.99` | `confirm`：默认选中推荐主题，等待确认 |
| `45–69.99` | `candidates`：展示多个候选，不自动选择 |
| `<45` | `manual`：建议新建主题或人工分类 |

`auto_eligible` 不等于分类器直接写库。分类器始终只返回建议；接受和撤销由 `KnowledgeRepository` 对应的 Rust 持久化用例统一执行并记录操作日志。

低于候选阈值、只靠历史活跃度、只靠相对全文排名或没有直接主题证据的 Topic 不进入候选列表。FTS5/BM25 只有在同一短语也出现在用户可见投影时才能贡献分数；长正文的本地集合相似度使用首、中、尾确定性采样，避免主题词被大量正文稀释。此时返回空建议并显示“无充分证据”，不得用 0 分或弱相关主题填满界面。

### 导入后的自动整理

- 导入器返回本次实际新增的 Source Item ID；自动整理只处理这些 ID，并先去重。
- 当库中已有来源但没有 Topic 时，使用既有个人目录提案增量建立可编辑的 Domain/Topic；不得覆盖原文或已有目录。
- 个人目录 v3 以 47 个可编辑主题覆盖投资市场、半导体与算力、宏观与楼市、AI/软件、Git、备份恢复、网络、网站、设计创作、影视/VFX、海外账号金融、汽车、医疗、教育职业、长期事务和社会文化等主要资料簇；目录规则只使用能独立说明主题的短语。
- 知识工作区首次加载当前目录版本时，通过同一仓库入口幂等补齐目录；应用 v3 只停用旧版 `catalog-rule-*` 宽泛托管规则，不覆盖用户自建规则、已有来源归类和原始正文。
- 每条新来源仍统一调用 `classifySource`，并保存候选、分数、理由、信号贡献和算法版本。
- 只有 `auto_eligible`（`≥90`）可以由自动整理用例确认；确认必须写操作日志，并允许按批次撤销。
- `confirm`、`candidates` 和 `manual` 只保存为待确认建议，不得为了提高自动归类率降低阈值。
- 收录箱可以对已加载的旧来源执行同一自动整理用例；不得复制分类权重或产生第二套页面规则。
- Domain/Topic 的名称和描述允许用户编辑；编辑保留 ID、来源归属、判断、证据和关系。

### 确定性

- 相同来源、主题、规则、历史、FTS 分数和算法版本必须得到相同排序与分数。
- 时间不能在分类器内部读取“当前时刻”，必须由输入或来源日期提供。
- 同分候选使用稳定 Topic ID 排序。
- 禁止网络请求、模型调用和隐式随机数。

### 解释

每个候选至少返回：

- Topic ID 与完整主路径；
- 总置信度和阈值结果；
- 五项信号的归一化分数、权重和贡献分；
- 实际命中的规则、别名、实体、全文、关键词或历史原因；
- 算法版本和生成时间。

## 结构操作

- Topic 合并必须先生成影响预览。
- 合并提交前保存参与主题的完整快照。
- 被合并主题保留为别名并建立旧路径重定向。
- 来源、笔记、判断、证据和问题不得因合并丢失。
- 操作日志必须保存 before/after 快照和撤销状态。
- 首版 Topic 拆分只生成方案和内容归属预览，不提供直接提交。

- `src/knowledge/classificationFixtures.ts`：固定验收数据，不是生产词典。
- `src/services/knowledgeAutoOrganizer.ts`：导入后和收录箱批量整理的唯一前端编排；只调用分类器和仓库公开用例。

- `src-tauri/src/knowledge/repository.rs`：正式知识仓库，负责 Source Item 回填、分类确认/撤销、主题详情、判断、证据、问题、上下文、合并和关系。
