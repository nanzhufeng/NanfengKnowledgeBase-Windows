# 数据位置迁移与历史附件搜索合同 v79

## 本轮目标

- 设置中的数据位置允许选择新的空目录，并在用户二次确认后迁移。
- 全部笔记的搜索框支持正文、图片、视频、音频和文件的历史检索；图片可直接预览，其他附件回到所属笔记后使用统一预览层。

## 数据位置的唯一所有者

`src-tauri/src/paths.rs` 负责数据目录选择、预检、复制校验、下次启动配置和撤销切换；页面不拼接或复制任何正式路径。

迁移顺序固定为：预检空目录与磁盘空间 → SQLite 在线备份和 `integrity_check` → 导入/附件/导出/备份/日志逐文件 SHA-256 校验 → 写入下次启动的独立配置 → 用户重启。

- 源目录不修改、不删除。
- 当前进程始终继续使用旧目录。
- 复制或校验失败时不写路径切换配置。
- 已安排的下次启动切换可撤销；撤销不删除新目录副本。

## 附件历史搜索的唯一所有者

`src-tauri/src/attachments.rs::search_attachments` 只读取 SQLite 中已受控归档附件的文件名和 MIME 元数据，按 `all / image / video / audio / file` 分类并限制返回数量。前端只显示结果和调用既有 `AttachmentPreview`，不扫描本机目录、不解压压缩包，也不宣称具有 OCR 或音频转写。

## 验收与边界

- 新的中文双击入口：`启动南枫知识库-数据路径迁移与历史附件搜索验收.bat`。
- Codex 已完成 `npm run typecheck`、前端 211 项和 Rust 90 项测试；其中包含迁移保留源目录与附件分类检索的定向合同。
- 隔离 Tauri `--no-bundle` 构建在本轮两次均超过外层 120 秒时限，未产生可验收 EXE；未启动应用、未读取或写入正式数据。
- 真实桌面验收时必须由南烛枫自行双击 BAT，先在新建空目录完成预检与确认，再检查重启后的数据、附件预览和旧目录保留情况。
