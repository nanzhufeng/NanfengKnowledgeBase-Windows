# 南枫知识库开发设计系统

> **跨项目参考入口。** 当南烛枫说“参考南枫知识库的开发文档”“照南枫知识库当前效果做”“沿用南枫知识库的苹果风和交互”或含义相近的话时，Codex默认先完整读取本文件，再按本文路由读取对应权威文档。不能只提取色板、玻璃透明度或一张截图。

## 1. 这句话默认代表什么

“参考南枫知识库的开发文档”默认要求新项目继承以下**方法与体验关系**：

1. 产品、布局、交互、视觉、示例内容和验收证据分层锁定；
2. 主内容优先、辅助文案克制、信息层级清楚；
3. 浅色苹果式材质角色、相对明暗、圆角、边缘融合与性能回退；
4. 桌面自适应多栏、独立滚动、固定控制区和窗口状态连续性；
5. 搜索、筛选、卡片、列表、菜单、弹窗、返回和图片预览的完整交互合同；
6. 精细指针、键盘、触控、减少动态、减少透明和高对比适配；
7. 自然语言反馈翻译、受限微调、样板先行与同语义消费者同步；
8. 设计、代码、测试、构建、隔离环境、真实设备和发布证据分层报告。

这句话**不会默认继承**南枫知识库的业务名称、主题/命题/证据数据模型、三个入口名称、数据库结构、自动分类阈值、背景图片、正式数据目录、旧版本号、BAT名称或固定窗口尺寸。只有南烛枫明确点名时，其他项目才能借鉴这些项目专属事实。

## 3. 开始新项目时先锁定六层

每次引用本系统，先在新项目任务合同中写清：

| 层级 | 要确认的内容 | 默认处理 |
|---|---|---|
| A 产品与信息架构 | 第一用户任务、对象、入口和主流程 | 只参考方法，不复制知识库业务 |
| B 页面功能布局 | 栏位、模块、主次、固定区与滚动区 | 桌面可高保真参考，移动端需转换 |
| C 交互行为与状态 | 点击、悬浮、焦点、返回、弹窗、恢复 | 默认继承语义和结果 |
| D 视觉皮肤与材质 | 色彩、玻璃、圆角、阴影、边缘、动效 | 默认继承角色和关系，不复制死数值 |
| E 示例内容与数据语义 | 标题、计数、日期、业务文案 | 默认不继承 |
| F 验收证据 | 参考视口、测试、构建、真机和发布 | 默认继承分层方法，不冒充已验证 |

用户只点名一层时，其余层保持不变。用户说“方向没错，只优化精细度”时，自动切换到低自由度受限微调，不能重新设计未点名层级。

## 4. 视觉和材质系统

### 4.1 默认视觉方向

- 默认整体明亮、自然、高可读；不使用大面积暗色、赛博、游戏面板或过度发光。
- 图片预览、视频监看等需要突出媒体的专用工具可以局部暗底，其他生产力界面保持浅色。
- 深蓝承担正文和结构身份，橙色承担选中与主要动作；红、绿等只承担警告、错误、事实、成功或判断语义。
- 一屏只保留一个主色和一个强调色，避免多种高饱和色争抢内容。

### 4.2 六类材质角色

新项目按角色建立Token，不按页面复制颜色：

| 角色 | 职责 | 层级关系 |
|---|---|---|
| 侧栏/全局导航 | 品牌、一级入口、全局状态 | 信息清晰优先，选中态完整点亮 |
| 工作区承托 | 容纳栏位、场景和留白 | 低纯白、低干扰，不抢前景 |
| 内容/阅读表面 | 正文、证据、详情和稳定信息 | 比直接父层更清楚、更稳定 |
| 高频控制 | 搜索、筛选、标签页、定位和排序 | 比所在列表卡更亮，聚焦不跳层 |
| 浮层 | 菜单、组合筛选、提示 | 来源明确，可立即关闭 |
| 模态/专用工具 | 弹窗、导出、预览和维护任务 | 保持上下文，可有明确视觉例外 |

语义绿、红、橙和紫只叠加在共享明度骨架上，不另建一套曝光体系。

### 4.3 场景皮肤和经典浅色

- 经典浅色必须独立成立：实体浅色表面、深色文字和清晰边界，不依赖背景图或实时模糊。
- 场景皮肤保持原图清晰，只在承载文字与操作的区域铺浅玻璃；空白区域允许看见环境。
- 场景背景只影响直接落在图上的文字对比；持久卡片不根据背景动态重算RGB或透明度。
- 环境冷暖通过固定低色度玻璃自然透入，不用明显蓝绿或相反色补偿“中和”背景。
- 减少透明、高对比或不支持模糊时切换为实体浅色表面，功能和主要层级不能减少。

### 4.4 明暗、透明和色阶

- 前景表面必须比直接承托层更清楚，但不能用连续纯白板抢正文。
- “提高相对亮度”优先调整前景与直接父层的低色度明度差，不默认改变已确认的透明度和模糊职责。
- “压暗”只作用于被点名的消费者，不联动整个工作区或所有白色卡片。
- 大承托面可以更通透，正文、证据和高密度信息使用更稳定表面；层级不能只靠不断降低透明度。
- 共享低对比渐变可加入极轻中性抖动消除色阶，不能形成可见噪点、颗粒或新的色温。

### 4.5 边缘、圆角和阴影

- 外层表面在到达裁切边缘前，以低对比明暗渐退自然融入环境。
- 禁止连续等亮白线、闭环白描边、统一渐变描边、2px双向mask和为所有卡片叠加同一高光。
- 已模糊工作区中的持久卡片和固定控制层不再嵌套实时`backdrop-filter`，避免WebView/GPU分块亮带。
- 完整边界只服务选中、焦点、警告等明确状态。
- 阴影少而稳定，重点落在卡片底部；不能一帧跳出、扩散到上方或形成大范围装饰性发光。
- 同类组件共享圆角比例；固定头、底板和滚动裁切处不能突然出现直角或白色硬块。

## 5. 桌面布局与窗口

- 桌面生产力界面优先使用全高主导航、较窄浏览/列表栏和主要阅读区；阅读空间永远优先。
- 多栏各自拥有真实滚动容器。一个列表滚动不能带动搜索、筛选、标题、模块导航或相邻详情漂移。
- 窗口可随时调整；参考截图只用于同条件比较，不能参与运行时尺寸、中心点或图片位置计算。
- 最小窗口优先保留主任务和命中范围，再收起次要栏、转抽屉或切单列，不通过压缩文字和按钮勉强维持三栏。
- 换肤、窗口调整、断点变化和生命周期恢复不能丢失选择、筛选、滚动、展开状态或未提交草稿。
- 若用连接线表达列表与详情关系，端点读取卡片真实几何，只跨卡片间隙，不使用页面私有负像素补偿。

南枫知识库的`1702×1066 / 100% / 1×`是桌面正式视觉比较条件，不是其他项目必须使用的固定窗口。

## 6. 搜索、筛选和焦点

- 搜索和筛选属于高频控制层，必须比所在列表承托层更亮、更容易定位。
- 同类搜索框共用默认、悬浮、聚焦、编辑、禁用和错误状态。
- 聚焦只在默认空间投影与内高光之上叠加焦点环；不得用另一条完整阴影覆盖默认态，导致点击后突然贴平。
- 筛选按钮可以比搜索框视觉更轻、更精致，但不能缩小真实命中范围。
- 搜索、筛选、排序、数量、状态和快速定位属于固定控制区；长列表/正文是独立滚动区，两者在结构上分开。
- 组合筛选支持重置、应用、点击外部关闭和`Escape`关闭，关闭后焦点回到触发按钮。

桌面紧凑筛选的当前种子值可参考约42px命中高度、胶囊圆角、12px文字和15px图标；其他项目必须按密度、平台和可访问性校准，不能盲目复制。

## 7. 滚动和固定控制层

### 7.1 悬浮即拥有滚轮

- 桌面并排或嵌套的独立滚动卡片在指针悬浮后立即接收普通纵向滚轮，不要求先单击或改变键盘焦点。
- 更接近指针的真实滚动层优先；到达边界后才允许外层继续处理。
- 不劫持`Ctrl/Cmd + 滚轮`、横向滚轮、系统缩放或键盘焦点。
- 触控平台没有hover：触摸落在哪个滚动容器，就由该容器直接接管手势。

### 7.2 固定搜索/筛选层

- 固定控制层必须位于真实滚动结构中，几何位移为0；不要先随整卡滚动再用阈值属性补偿。
- 下方内容经过时只留下不可辨认的色影与连续柔和承影，不能看清文字。
- 底部承影与窄幅材质渐退常驻、连续、圆润，不在滚动阈值处一帧跳出。
- 禁止顶部1px白色高光、白色硬块、硬分割线、整块阴影切换和嵌套实时模糊。

## 8. 卡片和列表交互

### 8.1 紧凑小卡逐卡微交互

所有视觉上成立的紧凑小卡共享同一轻抬升手感，但分成两个语义角色：操作卡拥有悬浮与按压，纯阅读内容卡只有悬浮，不能用按压伪装成可点击。

- 只在精细指针hover时整体上移约2px，并平滑增强底部投影；
- 按下可缩放约0.985；
- 键盘焦点保持几何稳定，只增强焦点环或投影；
- 明确去向的尾部箭头或外链图标可前移1–2px；
- 使用明确的`transform/translate/scale/box-shadow`过渡，不使用`transition: all`；
- 不为大量列表卡常驻`will-change`；
- `prefers-reduced-motion`下取消位移和缩放；
- 角色直接挂在每张最深层独立小卡，不挂给截图中的整组、网格、横向链路、父容器或页面外壳；
- 禁止抬升角色嵌套；动态区域为空时可由空态小卡消费，有子项时改由每个子项分别消费；
- 大面板、连续正文、表单和纯布局承托层不抬升；悬浮一张时兄弟卡与父容器必须保持静止。

### 8.2 选中、悬浮和快捷操作

- 选中态表达当前对象，悬浮态表达可操作，二者不能互相替代。
- 侧栏所有分组的选中态共用同一完整点亮：强调文字、侧边指示、浅暖表面、低对比完整边界和克制抬升共同出现。
- 列表快捷操作默认只在hover时出现；选中卡片或卡片本身获得焦点不让操作长期占位。
- 键盘实际聚焦操作按钮或菜单已展开时，快捷操作继续显示。
- 操作显隐不能改变卡片宽高、文字换行或列表位置。
- 整行单击负责选择/切换时，外链、删除、收藏和更多等另一语义动作必须限制在自己的图标命中区。

## 9. 导航、返回、菜单和弹窗

- “返回上一级”返回真实进入前的位置，不统一写死某个默认页；只有没有来路的直接入口才使用产品规定的安全默认目标。
- 从多个面板进入同一内容时，保存来源面板、对象和返回所需位置；正文锚点只可作为证据元数据，不能在打开内容时自动滚动。正文定位必须由用户本次明确提交搜索触发。
- 三点菜单、组合筛选、轻量浮层和弹窗支持点击外部关闭、`Escape`或系统返回，关闭后恢复触发源焦点。
- 菜单从触发源附近出现并保持在窗口内，不因滚动或缩放脱离来源。
- 大弹窗固定标题、主要动作和必要脚注，只有中间长内容滚动；弹窗外壳与正文不能同时滚动。
- 不同弹窗拥有独立尺寸身份，不继承无关弹窗的旧尺寸；小窗口提供最小尺寸和单列回退。
- 删除、覆盖、恢复、导入和发布等有影响动作保持明确确认、进度、结果和失败恢复，视觉顺滑不能掩盖风险。

## 10. 图片和媒体预览

图片与视频属于同一“视觉媒体预览”角色，共用专用暗底、视口状态和窗口行为，并继续继承关闭、焦点、快捷键和可访问性合同：

- 默认使用当前应用可用视口，不使用历史固定窗口尺寸。
- 图片以`naturalWidth × naturalHeight`、视频以`videoWidth × videoHeight`建立真实尺寸渲染面，首次读取真实画布后完整适配并居中。
- 图片保留原始像素上限，小图不强制放大；视频允许在不裁切的前提下等比放大，尽量铺满软件可用画面。
- 明确区分`fit`与`custom`：fit随窗口变化重新适配；用户缩放或拖动后才进入custom并保留检查位置。
- 桌面`Ctrl/Cmd + 滚轮`以光标为中心缩放，左键拖动画布；中键恢复当前可用区域并重新完整适配、归零和居中。
- 移动端用双击或明确的“适合屏幕”动作替代中键，不能伪造桌面输入。
- 100%只表示原图1:1，不把“适合窗口”冒充100%。
- 图片与视频的画布、标题栏和外壳使用低干扰暗底，视频元素自身固定纯黑承托；文本、PDF等文档可继续使用浅色阅读环境。
- 视频底部原生播放控制条优先接收指针；适配态点击视频仍可播放/暂停，缩放进入custom后可拖动视频内容区，控制条不被视口手势抢占。
- 已属于笔记内容的图片、视频、音频、PDF、TXT等附件默认加载和原位呈现，不把“点击恢复”作为日常阅读前置步骤；本地大文件采用顺序或有界加载，单项失败不得阻断其他文件。
- 历史附件筛选的完整目录来自原文声明与已受控实体并集，不能只查询已经物化的文件。全部/图片/视频/音频/文件共享同一目录，长列表按月分组并独立滚动。
- 图片/视频分类必须直接形成可辨认的媒体库：图片显示真实缩略图，视频在本地抽取代表帧并提供明确播放标记；点击继续进入统一最高层预览器。PDF/TXT/普通文件保持信息列表，不伪造封面。
- Markdown附件必须由受控读取命令明确解码后交给统一Markdown阅读器，不能使用本地文件iframe让WebView猜字符集；正文原位与放大预览共用读取/渲染所有者。普通文本自动换行，代码块和表格只在自身内部横向滚动。

## 11. 内容密度、空态和完整阅读

- 辅助文字只在帮助判断状态、定位来源或完成操作时保留。
- 删除重复页面标题、职责复述、阅读说明、无价值占位和纯装饰性元信息。
- 列表项优先展示标题、真实语义元数据、日期/状态和必要动作；真实验证长中文标题、长英文文件名和三位数计数。
- 空态说明发生了什么并给出下一步，不用大块不透明白板填满空区域。
- 大量内容采用紧凑摘要 + 明确“查看全部/详情”入口；入口必须真正展示完整内容，不能再次截断。
- 视觉层级不能通过降低正文、图标、计数和底部状态的透明度实现。

## 12. 平台适配

| 体验意图 | Windows/macOS/桌面Web | 平板 | iOS/Android手机 |
|---|---|---|---|
| 主导航 | 全高侧栏或平台原生侧栏 | 可折叠侧栏/导航分栏 | 系统导航栈或底部一级入口 |
| 浏览+阅读 | 窄列表栏+大阅读区，可三栏 | 横屏双列，竖屏导航分栏 | 列表进入详情的单列任务流 |
| hover与快捷操作 | 支持精细指针反馈 | 有指针才启用 | 无hover，使用按压/上下文菜单 |
| 返回 | 保存真实来路和窗口状态 | 保存来路并支持系统返回 | iOS导航返回/Android预测返回 |
| 筛选 | 固定头和组合浮层 | 顶部或侧边筛选面板 | sheet、bottom sheet或全屏筛选 |
| 图片复位 | 中键与明确按钮 | 双击/明确按钮 | 双击/明确按钮 |
| 弹窗 | 可调窗口、菜单和快捷键 | 大sheet或分栏弹层 | sheet、全屏页或系统确认框 |
| 材质 | 可使用共享浅玻璃与单次模糊 | 控制模糊面积与内存 | 优先系统材质与实体回退 |

平台可以改变容器、栏位数量、菜单位置、手势和系统控件，不能改变对象含义、操作结果、危险动作确认、返回目标和信息优先级。

## 13. 自然语言反馈合同

南烛枫可以继续使用“太亮、太透、发灰、白线、硬边、层次不足、方向没错别大改”等自然语言。Codex负责将其翻译为：

1. 目标对象及其直接父层；
2. 相对关系，而不是孤立数值；
3. 唯一主要变量；
4. 必须保持不变的材质、布局、交互和数据；
5. 样板页面、状态、平台、视口和证据；
6. 同语义消费者与明确排除对象。

“所有类似问题”表示先寻找共同语义角色和唯一所有者，不授权使用全局通配选择器。一次只改变一个主要视觉变量，样板确认后再同步。连续两次未命中时停止继续调参数，回查对象映射、CSS层叠、滚动所有权、命中范围和GPU/WebView合成。

## 16. 最小引用顺序

以后在其他项目中，南烛枫只要说“参考南枫知识库的开发文档”，Codex默认执行：

1. 读取本文件；
2. 读取当前设计基线与验收矩阵；
3. 根据任务读取架构所有权、协作复盘或皮肤经验；
4. 写清继承、适配和不继承项；
5. 先完成一个真实样板；
6. 样板确认后再同步同语义消费者和目标平台；
7. 按证据等级汇报并在达到当前合同后停止。

这条自然语言路由不授权读取或写入南枫知识库正式数据，也不授权把南枫知识库业务结构直接复制到其他软件。
