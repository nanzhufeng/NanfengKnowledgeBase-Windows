# 南枫知识库交互性能架构

更新时间：2026-08-02

## 目标与保护边界

本轮目标是让入口点击、列表切换、搜索、滚动和长正文阅读不再与目录维护、历史分类或重复装配争抢主线程。优化必须保持三入口、四种知识状态、四套皮肤、四个统一笔记列表、关联线、快速定位、正式对象语义和数据读写结果不变。减少首屏数量只作为安全上限，不是主要性能方案。

不触碰的边界：

- 不修改 migration v4 表结构或知识对象含义；
- 不删除功能、页面区块、皮肤或正式正文；
- 不后台启动应用，不打开、写入或迁移正式 `D:\南枫知识库`；
- 不用静态假数据、分页截断或降低图片质量冒充架构优化。

## 唯一性能链路

| 层级 | 唯一职责 | 当前实现 |
|---|---|---|
| Tauri 调度 | 数据库、文件和导出命令不得占用 WebView/UI 主线程 | `src-tauri/src/commands.rs` 的 99 个命令统一使用异步命令调度；底层仍通过同一 `AppState` 和 SQLite 连接串行保护数据 |
| Repository IPC | 同一时刻相同读取只发起一次 IPC；选中正文短期复用 | `KnowledgeRepository.coalesceRead` 合并重复读取；最近 8 篇来源正文使用有界内存缓存 |
| SQL 读取模型 | 列表只取摘要；正文只在选中后读取 | 来源档案列表只在标题确需正文回退时携带正文；普通标题不再把 `original_text` 搬入列表行；JSON 检查先判断结构首字符 |
| 入口数据所有权 | 首屏、补充数据和维护数据不得互相阻塞 | `knowledgeWorkspaceData.ts` 将来源入口拆成“轻量档案首屏”和“来源筛选/主题名称补充”两条链；知识视图只读领域与主题；别名、实体、规则和目录提案只归主题管理 |
| 会话连续性 | 重新挂载先恢复已读轻量快照，再后台复核正式库 | `KnowledgeWorkspace` 复用 `App` 的同一 Repository，并保留仅限当前进程的来源、领域、主题和来源目录快照；快照不持久化、不写库、不替代正式事实 |
| 计算隔离 | 确定性分类不能在 WebView 主线程形成长任务 | `classification.worker.ts` 与 `classificationWorker.ts` 承担正式分类；导入后整理、单篇计算和历史升级统一异步等待 Worker 结果 |
| 后台维护 | 历史升级不得在入口点击后立即抢占交互 | `interactionScheduler.ts` 先保护 1.2 秒交互窗口，再等待空闲；每条来源前主动让出主线程，离开来源入口立即取消未完成任务 |
| React 更新 | 输入、入口和选择反馈优先，重计算可延后；稳定内容不重复解析 | 搜索、记录入口范围和长正文解析使用 `useDeferredValue`；导航计数使用 `useMemo`；补充数据使用 `startTransition`；Markdown 预处理和组件使用 `useMemo/memo` |
| 滚动与几何 | 一帧最多测量一次；亚像素变化不触发状态更新 | `useRafScheduledCallback` 合并 scroll/resize/ResizeObserver；`connectorMetricsEqual` 抑制无意义关联线重绘 |
| 绘制 | 数据仍在 DOM，远离视口的重内容延后绘制 | 长对话、假设、决策版本和时间线使用 `content-visibility:auto` 与自动记忆真实尺寸，不改变快速定位或滚动语义 |

## 后续防回退规则

1. 新增数据库或文件命令默认使用异步 Tauri 命令；确需同步时必须证明耗时恒定且不访问磁盘。
2. 列表读取模型不得返回完整正文、附件字节或完整知识上下文。
3. 同一页面不得在多个 effect 中重复请求同一对象；重复读取应由 Repository 合并。
4. scroll、resize 和 ResizeObserver 不得直接高频 `setState`，统一按动画帧调度并比较新旧几何。
5. 搜索输入不得同步触发大列表重算或 Markdown 全量重解析。
6. 优先修复调度、数据形状、重复工作和绘制范围；减少笔记数量只能作为数据安全上限。
7. 来源入口关键路径不得读取目录提案、别名、实体或分类规则，不得应用目录或启动历史升级。
8. 任何可能遍历多篇正文的计算默认进入 Worker；后台维护必须可取消，并在每个独立工作单元之间让出主线程。
