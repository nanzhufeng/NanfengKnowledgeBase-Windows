# 历史附件恢复与统一预览 v80

日期：2026-08-08

## 已确认事实

- 正式库只读核对发现：至少 `150` 条历史笔记声明了 `439` 个有文件名的附件。
- 这些记录来自 Claude 的 `conversations.json`。JSON 只保存文件名、UUID 或提取文本，不含图片、视频、PDF、TXT、DOCX 等二进制文件。
- 因此“原附件尚未进入受控目录”不是前端漏判某一种格式，而是附件归档和关联从未发生；没有真实文件时软件不得伪造预览。

## 唯一恢复路径

`src-tauri/src/attachments.rs` 现在拥有历史附件恢复：

1. 读取历史笔记声明的附件名；
2. 用户在设置中明确选择旧附件文件夹；
3. 只对唯一同名的真实文件做匹配；同名多份或找不到时保持未匹配；
4. 复制到受控 `attachments` 目录，计算 SHA-256 并按记录去重；
5. 写入附件关联后，所有来源页面统一读取该受控附件。

这个过程不删除、移动或覆盖用户选定目录中的任何原文件，不改笔记正文。设置弹窗先显示可恢复、未匹配和已有 ZIP 数量，只有用户点击“确认恢复已匹配附件”才写入正式库。

ChatGPT ZIP 仍按已有受控归档素材恢复；无法从任何原始包或所选文件夹获得的二进制文件会保留为未匹配，不能被误称为已恢复。

## 统一展示标准

- 图片：来源正文直接缩略显示；点击进入软件内图片预览。
- 音频和视频：来源正文直接提供媒体控件；点击可进入软件内预览。
- PDF、TXT、Markdown、JSON、CSV、日志和 XML：点击后在软件内查看。
- DOCX、压缩包及没有可靠 WebView 渲染器的文件：保留受控文件，明确提供“打开原文件”后备动作；不执行压缩包内容。

分类唯一入口为 `src/attachments/attachmentPreview.ts`，来源正文展示唯一入口为 `src/components/SourceAttachmentAsset.tsx`，避免页面各自猜测格式。
