# 南枫知识库验收与回归计划

现行用户可见名称只使用`主题洞察 / 全部笔记 / 主题管理`。测试中的`knowledge / sources / Record / listSourceArchive`是内部兼容标识；历史计数和旧审计中的`收录箱 / 来源档案 / 知识视图`只保留证据语义，不得成为新断言。

## 当前验证边界

当前代码已经接入正式知识 UI、Tauri 命令、Rust/SQLite 知识仓库和 migration v4 对象；历史 migration v3、隔离副本迁移、完整恢复、失败回滚、隐藏命令桥和可见 BAT 用户路径均保留原层级证据。当前正式`D:\南枫知识库`未由本轮 Codex 打开或应用 migration v4。以下内容仍不能标记为完成：

- 拆分提交（首版明确不提供，除非用户重新确认产品边界）；
- 外部图片/链接在用户实际默认应用中直接前台显示的最终 BAT 确认；
- GitHub Release。

## 自动回归门槛

每次 checkpoint 至少运行：

1. `npm test -- --run`：前端领域、导入内容、Markdown 和仓库合同。
2. `npm run test:rust`：SQLite migration、知识仓库、导入、附件、备份恢复和安全边界。
3. `npm run test:sites`：静态部署回退合同。
4. `npm run typecheck`：TypeScript 边界。
5. `npm run build`：Vite 生产构建与 Sites 产物。
6. `npm run test:e2e`：无界面核心流程和正式知识入口。
7. `git diff --check`：空白错误。

自动回归只能证明合同与无界面交互通过，不能替代真实桌面或正式数据验证。

## 正式知识入口合同

1. 默认应用入口显示`主题洞察 / 全部笔记 / 主题管理`；旧收录箱并入全部笔记，旧主题浏览器与整理工作台并入主题管理，不再暴露假数据原型路由。
2. 浏览器无 Tauri 桥接时显示诚实空状态，不注入业务假数据。
3. 全部笔记显示真实 Source Item、原文、自动归类结果、笔记数和主题归属；无正文空会话默认隐藏但保留数据，无充分证据时不得展示 0 分候选。
4. 最高候选严格`>65`时默认自动归类并记录可撤销操作；`45–65`保留候选，`<45`进入人工例外处理。
5. 主题洞察默认读取竞争假设，并在同一阅读区切换判断演变、主题整合和决策账本；主题整合只显示一个成果。关联笔记/来源的卡片主体只在当前页切换正文，最右侧外链图标才进入全部笔记，整卡不得跳转；原始笔记/来源继续只承担输入、正文切换与回溯。四个面板进入笔记后，`返回上一级`必须回到原面板并定位原来源；直接进入全部笔记时默认回到竞争假设的对应来源。任何方式打开或切换笔记都必须清空旧正文查询/高亮并从正文顶部开始；只有本次手动提交正文搜索才允许滚动。正文历史点击只回填输入，不自动搜索。
5a. 侧栏不得显示`判断更新`人工入口；`updated`历史记录状态只作为兼容数据和共享筛选值保留。批量导入与字段映射导入必须共同调用App唯一自动整理队列；导入中断后，下次启动按分类算法版本标记自动续接，完成后刷新主题洞察和全部笔记读取模型。
6. 主题管理读取真实领域/主题边界、自动归类依据、层级关系、别名和待处理事项；维护入口为次级操作。零来源主题保持在列表中，但不得仅因零来源进入待处理筛选、生成检查任务或要求用户逐个判断。
   - 顶层叶子主题不得显示由“领域直属 / 暂无子主题 / 暂无关系 / 0个对象”组成的占位区；存在真实父主题或子主题时，`主题层级`只列实际内容。
7. 合并必须先预览影响，再事务提交，并可撤销。
8. 同时拥有当前判断的两个主题不得直接合并，必须先由用户处理冲突。
9. 拆分只提供只读方案，不显示伪提交入口。
10. 关系建议只生成确定性候选，人工确认后才写入。
11. 个人目录预览不写库，明确确认后增量、幂等写入且不覆盖已有主题。
12. 分类规则、主题别名和实体词典 CRUD 由 Rust/SQLite 持有；分类纠正写反馈并可撤销。
13. Note 与 Source Item 分离；Note 更新和归档不能覆盖原始来源正文。
14. Proposition 是独立对象；Turning Point 只由用户明确选择前后判断后创建，变化原因本身不能自动升格。
15. Evidence 锚点按来源类型校验；可信度、验证状态和有效状态分开持久化。
16. 浏览器桥接用例从最终主题洞察读取 Topic、Judgment、Source 等正式对象，确认旧`维护与录入`CRUD 不恢复为首屏路径；写入命令的字段与持久化合同由 Repository/领域测试覆盖。
17. 隐藏真实 Tauri/WebView2 在隔离根写入新知识对象，强制重启后按原 ID 读回，并以只读检查器确认 migration、计数、完整性和外键。
18. 新导入成功后只整理实际新增的 Source Item；知识工作区通过同一仓库入口幂等应用个人目录并停用旧版宽泛托管规则；首次加载自动补算全部旧来源并按当前版本完成标记断点续算。全量升级与新导入统一为：最高候选严格 `>65` 自动确认，`45–65` 仅保存候选。
19. Domain/Topic 重命名和描述编辑保留 ID 与已有关系。
20. 当前判断、TXT、Markdown 和平台会话使用统一 Markdown/角色卡阅读组件。
21. 快捷键弹窗使用独立尺寸键和内容自适应布局，不得继承其他通用弹窗的历史宽高；六项快捷键在桌面宽度下使用两列卡片，在小于760px时转为单列，1280×720与1702×1066均不得裁切或偏离视口中心。

## 性能合同

1. 全部笔记首屏最多读取 120 条轻量摘要，不在列表命令中传输完整 `original_text`。
2. 只有选中来源后才按需读取正文；切换来源时不得闪现上一条正文。
3. 超过 20,000 字的正文默认显示流畅预览，正文框内不叠加遮挡信息；“查看详情”以全部笔记同款大弹窗显示完整正文。
4. 旧来源详情、版本和附件只在对应来源页读取，全部笔记列表不预取。
5. 桌面宽屏仅左侧来源列表滚动；页头和右侧阅读/分类卡不得随左侧移动。
6. 正文预览占用主题归属之外的剩余高度；主题归属过长时只滚动自身。
7. 数据库、文件、附件、导出和备份类 Tauri 命令不得同步占用 UI 主线程。
8. 同一时刻相同 Repository 读取必须合并；来源正文缓存必须有固定上限。
9. scroll、resize 和 ResizeObserver 触发的关联线测量每动画帧最多执行一次，亚像素差异不得触发 React 状态更新。
10. 200 篇、每篇约 2 万中文字符的全部笔记摘要读取必须在 500 ms 合同内完成；1000 条记录摘要性能合同继续保留。
11. 搜索输入先反馈，列表筛选与长正文解析允许延后；不得用删除功能、减少正式数据或降低图片质量换取流畅度。
12. Playwright 必须运行生产构建预览；不得把 Vite 开发服务器首次即时编译耗时当作成品页面交互延迟。当前全量 E2E 为 14/14 通过。

- 知识表、FTS、外键和唯一约束创建成功。
- 迁移后 `PRAGMA integrity_check=ok` 且外键违规为 0。
- 隔离验证工具必须要求专用标记，并拒绝 `D:\南枫知识库` 和 `D:\南枫情报台`。

## 分类合同

固定权重：

- 显式规则 35；
- 别名与实体 25；
- FTS5/BM25 20；
- 集合相似 10；
- 时间历史 10。

固定阈值：

- `65.01`：最高候选具备自动接受资格，仍必须记录操作并可撤销；
- `65`：候选列表，不得自动接受；
- `45`：候选列表；
- `<45`：人工处理或建议新建主题。

每条验收数据至少检查：原件先归档、提取完成后分类、相同输入可重现、分数与理由可解释、失败不影响其他队列项、无网络和模型 API 仍可运行。

分类 v5 固定回归样本至少覆盖：

- A股交易新规 → `A股与基金市场`，不得出现车型、转写或模型成本；
- 理想 i8 二手选择 → `新能源车与二手车`；
- A 型血输血 → `血型与输血`；
- 艺术专业报考 → `艺术与设计升学`；
- giffgaff Wi-Fi Calling → `海外通信与号码`；
- 美国银行卡方案 → `海外银行与支付`，不得因原始 JSON 中的 `Claude`、`Google`、`SRT`、`ACES` 或 `GPU` 生成候选；
- 日本楼市跌幅与分化 → `房地产与楼市研究`，不得因地点不同误塞入南京租房；
- 南枫批量改名设计 → `品牌、图标与界面设计`；
- GitHub 分支保护建议 → `Git 与版本控制`，不得只因出现 Codex/GitHub 归入 Agent；
- 账本恢复失败原因 → `数据备份、迁移与恢复`；
- 无消息、无名称、无摘要的会话 JSON 不进入默认收录箱列表，同时数据库记录仍保留。
- `Untitled`、单字或错误标题只要用户可见正文有明确主体，仍须由正文生成候选。
- 无候选来源必须保存当前版本完成标记；再次启动只处理未完成来源。

目录覆盖回归还必须验证：

- 托管主题名和跨主题短语不重复；
- `ChatGPT`、`Claude`、`Google`、`Apple`、`SRT`、`ACES`、`GPU`、`价格`、`视频`、`动画`、`设计`、`账号`、`GitHub`、`银行`、`汽车`、`投资` 等宽泛单词不能成为独立托管规则；
- 标题中的明确主题短语与正文命中走同一内容规则；
- FTS5/BM25 的命中短语必须同时存在于用户可见投影，原始 JSON 元数据不得单独提供全文分。

全量隔离覆盖审计还必须验证：

- 901 条来源全部进入同一分类器，不得只测试截图样本或首屏 120 条；
- 清晰正文无候选必须逐条复核，最终无候选只能是空记录、极短占位或没有业务主体的请求；
- fresh 隔离副本只应用当前目录版本，避免多轮调试残留规则污染结果；
- 上下文导出使用 `query_only`，导出前后写入计数和数据库哈希一致；
- 证据见 `docs/audits/2026-07-27-classification-v5-full-coverage/summary.md`。

## 数据与安全合同

- 远程 Markdown 图片默认不自动联网。
- 附件打开、删除和恢复只允许 canonical 受控路径。
- 完整迁移备份逐文件记录 SHA-256；旧版无哈希备份只允许预览。
- 恢复前校验文件集合、大小、哈希、数据库完整性和可用空间。
- 备份与恢复在后台工作线程运行，不阻塞 WebView。
- ChatGPT 完整 ZIP 按“消息 → 附件 ID → `.dat` 实体”映射，签名优先恢复格式，未知格式不猜测。
- 真实标题、正文、附件路径和原始导出包不进入 Git 审计摘要。
