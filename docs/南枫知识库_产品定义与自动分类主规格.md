# 南枫知识库：产品定义、自动分类与主题演化主规格

> 项目名称：南枫知识库
> 原项目名：南枫情报台
> 文档性质：产品定义 + 核心功能 + 信息架构 + 自动分类设计 + Codex 执行规格
> 文档优先级：最高
> 适用阶段：UI 原型、数据模型、分类引擎、MVP 开发与后续验收
> 核心原则：本地优先、离线可用、无强制模型 API、原始资料永远保留、自动整理可解释、所有自动操作可撤销

# 0. 给 Codex 的最高级指令

开始开发前，Codex 必须先阅读本文件，并遵守以下规则：

1. 本文件是当前项目最高级产品定义。与旧方案冲突时，以本文件为准。
2. 软件核心不是聊天、AI 总结或文件收藏，而是：
   - 自动分类
   - 主题框架
   - 跨时期整合
   - 关联
   - 合并
   - 拆分
   - 判断演化
   - 证据管理
   - 上下文复用
3. `.json` 是第一优先级导入格式。
4. 第一版不得依赖 OpenAI、Claude、Gemini 或其他云端模型 API。
5. 自动分类必须先以本地确定性算法完成，模型能力只能作为后续可选插件。
6. 自动分类不得直接不可逆地改动用户数据。
7. 所有自动关联、合并和拆分都必须：
   - 可解释
   - 有置信度
   - 有操作日志
   - 支持撤销
8. 原始文件、原始文本、原始 JSON 和导入结构必须完整保留。
9. UI 和交互流程必须先通过假数据原型验证，再接数据库和分类引擎。
10. 不得将项目做成普通笔记软件、聊天客户端、第二个 Notion 或第二个 Obsidian。
11. 任何新功能都必须回答：
   - 是否提高自动整理能力？
   - 是否增强跨时期主题整合？
   - 是否改善判断、证据和问题的追踪？
   - 是否减少用户重复研究？
12. 开发时小步提交，每个阶段更新：
   - `docs/CURRENT_HANDOFF.md`
   - `docs/DECISIONS.md`
   - `docs/TEST_PLAN.md`

# 1. 产品最终定义

## 1.1 一句话定位

南枫知识库是一个本地优先的个人研究与知识演化系统，用于统一接收来自不同 AI、文档、网页、音频、视频、转写和个人笔记的内容，并自动将它们整理到可持续演化的主题框架中。

## 1.2 核心目标

软件需要把零散资料转化为以下结构：

```text
大主题
└─ 子主题
   └─ 小主题 / 研究问题
      ├─ 笔记
      ├─ 来源资料
      ├─ 命题
      ├─ 判断版本
      ├─ 支持证据
      ├─ 反对证据
      ├─ 待验证问题
      ├─ 关键转折
      ├─ 决策与行动
      └─ 结果与复盘
```

软件最终要回答的不只是：

> 我保存了什么？

而是：

- 这些内容属于哪个知识框架？
- 哪些资料实际在讨论同一个问题？
- 哪些笔记应该归在一起？
- 哪些主题应合并或拆分？
- 我以前怎么看？
- 判断什么时候改变？
- 为什么改变？
- 当前结论由哪些证据支持？
- 哪些证据反对当前判断？
- 哪些问题仍未验证？
- 哪些资料已经过时？
- 下次继续向任意 AI 研究时，应带上哪些上下文？

## 1.3 软件的真正价值

软件价值不在于“比 AI 更聪明”，而在于：

> 把来自不同来源、不同时间和不同形式的信息，持续整理成用户自己的主题体系、证据链、判断演化和长期知识资产。

## 3.2 南枫知识库负责

- 统一导入不同 AI 和资料来源

- 自动分类笔记与来源资料
- 建立大主题到小主题的层级框架

- 维护知识有效期
- 生成下一次研究上下文
- 复盘决策与结果
- 导出、备份和迁移

正确关系：

```text
外部 AI
负责：

南枫知识库

组织、整合、追踪、复用和长期演化
```

# 5. 主题框架设计

## 5.1 必须支持层级树

基础结构：

```text
大主题
→ 二级主题
→ 三级主题
→ 具体研究问题
→ 笔记和来源资料
```

层级深度建议：

- UI 默认展示最多 4 层
- 数据模型不硬限制层数
- 超过 4 层时提示是否结构过细

## 5.2 不能只用纯树结构

现实知识存在跨主题关系。

因此每个主题需要：

- 一个主要父主题
- 多个相关主题
- 可选的其他父主题
- 主题别名
- 双向关联

示例：

```text
“数据中心电力需求”

主要路径：
投资 > 数据中心产业链 > 电力

相关路径：
AI 与软件 > AI 基础设施
能源 > 电网与发电
```

## 5.3 主题路径与关联必须分开

- 主路径用于分类和导航
- 关联关系用于表达跨领域联系
- 不允许因为跨领域关系而复制多份主题

## 5.4 主题别名

每个主题支持别名。

示例：

```text
正式名称：
Google 账号风控与封禁

别名：
谷歌账号被封
Google 风控
Gmail 登录封号
美区 Google 账号异常
```

所有别名参与搜索和自动分类。

# 6. 自动分类是软件核心能力

## 6.1 自动分类目标

对新导入的笔记或来源资料，系统需要自动完成：

1. 判断它属于哪个大主题。
2. 判断是否属于已有子主题。
3. 判断是否需要新建小主题。
4. 发现可能相关的其他主题。
5. 检测是否重复。
6. 判断是否应与已有笔记合并。
7. 判断现有主题是否过大，需要拆分。
8. 给出可解释的分类依据和置信度。

## 6.2 自动分类不能黑盒化

每次建议必须展示：

- 建议主题
- 置信度
- 命中的关键词
- 命中的别名
- 重合实体
- 相似历史笔记
- 时间关系
- 用户规则
- 为什么不是其他候选

示例：

```text
建议归入：
投资 > AI 资本开支 > 微软 AI 资本开支

置信度：
89%

依据：
- 标题包含“微软”“资本开支”
- 正文出现“Azure”“自由现金流”
- 与主题别名命中 3 项
- 与已有 4 篇笔记高度相似
```

# 7. 无模型 API 的本地分类引擎

第一版使用多层确定性规则。

## 7.1 第一层：明确规则

来源：

- 用户手动规则
- 文件路径
- 文件夹名称
- 来源平台
- 固定标签
- 导入模板
- 文件名模式
- JSON 字段

示例：

```text
文件路径包含“投资/美股”
→ 大主题候选：投资

来源平台 = Codex
→ 主题候选：软件开发
```

## 7.2 第二层：别名与实体词典

维护本地词典：

- 主题别名
- 公司
- 人物
- 产品
- 模型
- 行业
- 地点
- 项目名
- 用户自定义词

示例：

```text
微软 / Microsoft / MSFT
→ 同一实体

极氪7X / ZEEKR 7X
→ 同一产品实体
```

## 7.3 第三层：全文检索相似度

使用：

- SQLite FTS5
- trigram tokenizer
- BM25 排名
- 标题权重
- 摘要权重
- 正文权重
- 标签权重

## 7.4 第四层：关键词集合相似度

可使用：

- Jaccard 相似度
- Dice 系数
- 关键词重合率
- 标题 trigram 相似度
- 实体重合率

## 7.5 第五层：时间与历史行为

考虑：

- 最近正在研究的主题
- 同一天导入的同批资料
- 用户过去对类似资料的分类
- 用户曾确认的合并和拆分
- 主题最近活跃度

## 7.6 综合评分

建议评分模型：

```text
总分 =
明确规则 × 35%
+ 主题别名与实体 × 25%
+ 全文相似度 × 20%
+ 关键词集合 × 10%
+ 历史行为 × 10%
```

实际权重必须可配置和测试，不在 UI 中暴露过多技术细节。

## 7.7 置信度阈值

建议：

| 置信度 | 行为 |
|---|---|
| ≥ 90% | 可自动归类，但必须显示可撤销提示 |
| 70%–89% | 进入收录箱，默认选中推荐主题，等待确认 |
| 45%–69% | 显示多个候选，不自动选择 |
| < 45% | 建议新建主题或手动分类 |

高置信度自动归类也必须：

- 写入日志
- 支持撤销
- 在近期活动中显示

# 8. 自动关联设计

## 8.1 关联类型

支持：

- 同一主题
- 上下游关系
- 因果关系
- 对比关系
- 支持关系
- 反对关系
- 前置研究
- 后续更新
- 同一公司
- 同一产品
- 同一事件
- 同一项目

## 8.2 自动关联依据

- 主题重合
- 实体重合
- 引用关系
- 相同来源
- 时间接近
- 关键词相似
- 用户历史关联

## 8.3 关联建议

系统显示：

```text
可能相关：

- AI 资本开支与自由现金流
  原因：共同涉及资本开支、折旧和现金流

- 数据中心电力需求
  原因：共同涉及 AI 基础设施扩张
```

系统不自动创建弱关联。

# 9. 合并设计

## 9.1 何时建议合并

满足以下多项时提示：

- 标题高度相似
- 别名高度重合
- 主要实体一致
- 来源资料大量重叠
- 当前判断相似
- 用户经常在两个主题间来回移动
- 两个主题长期无法独立形成内容

## 9.2 合并预览

合并前必须展示：

- 两个主题的路径
- 当前判断
- 来源数量
- 笔记数量
- 命题数量
- 待验证问题
- 版本历史
- 冲突字段
- 预计主主题
- 将新增的别名

## 9.3 合并规则

- 用户选择主主题
- 次主题保留旧 ID
- 建立重定向
- 保留所有旧路径
- 次主题名称进入别名
- 冲突判断不得自动覆盖
- 重复来源只标记，不直接删除
- 合并生成操作快照
- 支持完整撤销

# 10. 拆分设计

## 10.1 何时建议拆分

系统可根据以下情况提示：

- 一个主题出现多个明显实体群
- 同一主题包含多个独立命题
- 来源资料形成多个不相交簇
- 当前判断无法写成一个统一结论
- 待验证问题分属不同方向
- 主题内容持续膨胀
- 用户频繁使用多个互不相关的标签

## 10.2 拆分候选

系统提出：

```text
当前主题可能拆分为：

1. 微软 AI 资本开支
2. Google AI 资本开支
3. AI 资本开支对自由现金流的影响
```

## 10.3 拆分交互

必须允许用户：

- 修改新主题名称
- 选择父主题
- 选择移动哪些笔记
- 选择移动哪些来源
- 选择复制哪些证据
- 选择保留哪些命题
- 选择待验证问题归属
- 预览拆分结果
- 确认后撤销

## 10.4 不得自动拆分

第一版只建议，不自动执行。

# 11. 笔记自动整理

## 11.1 笔记状态

- 收录箱
- 待分类
- 已分类
- 待提炼
- 已提炼
- 可能重复
- 已合并
- 已归档

## 11.2 自动整理动作

系统可以自动建议：

- 归入已有主题
- 新建子主题
- 添加标签
- 关联来源
- 关联相似笔记
- 标记重复
- 合并笔记
- 拆分长笔记
- 提取为命题
- 提取为待验证问题

第一版无模型时：

- 分类、关联、重复检测可自动完成
- 命题和问题提取以手动为主
- 后续可选本地模型插件再增强

## 11.3 笔记合并

合并笔记时：

- 保留原笔记
- 生成新整合笔记
- 原笔记标记为“已被整合”
- 新笔记记录来源关系
- 支持查看整合前内容
- 不直接覆盖原文

## 11.4 笔记拆分

拆分长笔记时：

- 以标题层级或用户选区拆分
- 每个子笔记保留回链
- 原笔记保留为索引页
- 不复制附件文件
- 所有操作可撤销

# 12. 跨时期主题整合

这是软件最关键的价值之一。

## 12.1 时间线

主题时间线包含：

- 新来源进入
- 新笔记创建
- 判断更新
- 证据新增
- 证据失效
- 问题解决
- 主题合并
- 主题拆分
- 决策产生
- 结果复盘

## 12.2 时间切片

用户可以选择日期，查看当时：

- 主题结构
- 当前判断
- 已有证据
- 未解决问题
- 当时来源
- 当时尚未出现的内容

## 12.3 判断演化

系统必须回答：

- 最初判断是什么？
- 哪次资料进入后发生变化？
- 哪个证据真正推动转折？
- 哪些只是重复信息？
- 当前判断和历史判断差异是什么？

## 12.4 关键转折

关键转折与普通更新时间分开显示。

只有以下事件进入关键转折：

- 判断方向变化
- 逻辑失效
- 重大证据出现
- 重要假设被推翻
- 决策发生改变

# 13. 命题、竞争假设与逻辑失效

## 13.1 命题层

一个主题下可以有多个命题。

示例：

```text
主题：
SaaS 公司下跌

命题：
- AI 会替代部分传统 SaaS
- 资本开支上升压制自由现金流
- 当前下跌主要来自估值收缩
```

## 13.2 竞争假设

允许多个解释并列：

- 假设 A
- 假设 B
- 假设 C

每个假设维护：

- 支持证据
- 反对证据
- 当前置信度
- 状态
- 失效条件

## 13.3 逻辑失效条件

每个重要命题和判断应支持填写：

```text
出现什么事实时，当前判断应被推翻或明显修正？
```

软件在每次更新主题时提示用户检查。

- 音频时间码
- 字幕行
- PDF 页码
- HTML 段落
- Markdown 标题
- JSON 节点
- 本地文件片段

UI 建议：

```text
左侧：
原始资料

右侧：
证据、命题和判断
```

点击证据后原始资料跳转到对应位置。

# 22. 自动分类验收标准

必须准备真实中文测试集。

至少覆盖：

- 投资
- AI
- 软件开发
- 海外账号
- 汽车
- 南京租房
- VFX
- 音视频转写

验收要求：

1. 高置信度分类必须有明确命中依据。
2. 自动分类错误可以一键撤销。
3. 用户修改分类后，系统保存新的规则或反馈记录。
4. 同一资料不能因为自动分类产生多个重复副本。
5. 合并不得丢失历史数据。
6. 拆分不得破坏原始资料。
7. 相似主题建议必须可忽略。
8. 自动整理过程必须离线可用。
9. 分类失败不能阻止资料进入收录箱。
10. 所有原始内容可以独立导出。

# 23. 差异化完成定义

软件必须能稳定回答：

- 这份新资料属于哪个知识框架？
- 它是否属于已有主题？
- 它与哪些旧笔记相似？
- 哪些主题可能重复？
- 哪些主题应该合并？
- 哪些主题已经过大，应拆分？
- 我以前怎么判断？
- 判断什么时候改变？
- 哪些证据促成改变？
- 哪些问题仍未验证？
- 当前知识是否过时？
- 下一次研究需要带上哪些上下文？

如果软件只能保存和搜索，它只是普通知识库。

如果软件能完成：

```text
自动分类
+ 框架整理
+ 关联
+ 合并
+ 拆分
+ 判断演化
+ 证据链
+ 未决问题
+ 上下文复用
```

它才具备真正独立和长期的开发价值。

# 25. 最终产品判断

南枫知识库不是“更好看的资料收藏器”。

它应该成为：

> 一个能够自行整理多来源笔记，建立主题框架，持续发现相似内容，协助关联、合并和拆分，并完整保存判断、证据、问题和变化历史的个人知识演化系统。

核心链路：

```text
多来源资料
→ 自动分类
→ 大主题与子主题框架
→ 笔记整合
→ 相似内容关联
→ 主题合并或拆分
→ 命题与证据
→ 判断演化
→ 决策与结果
→ 研究上下文复用
```

后续所有设计、架构和开发决策，都必须围绕这条链路展开。
