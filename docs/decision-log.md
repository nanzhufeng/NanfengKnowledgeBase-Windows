# 长期决策

| 日期 | 决策 | 原因 | 当前影响 |
|---|---|---|---|
| 2026-07-25 | 核心离线可用，不强制模型 API | 降低成本、维护和稳定性风险 | UI 不出现模型依赖 |
| 2026-07-25 | UI 与交互先于数据库 | 先确定真实工作流，减少后续返工 | 视觉契约已完成；生产路径已切换为 SQLite，浏览器数据只用于 UI QA |
| 2026-07-25 | JSON 是第一优先导入格式 | 适配 ChatGPT 与结构化资料归档 | 桌面端已实现归档、预览、字段映射、去重策略、日志和错误隔离 |
| 2026-07-25 | 使用单一深色左栏和浅色三栏工作台 | 保留科技质感，同时维持长内容阅读性 | 主界面结构固定 |
| 2026-07-25 | 卡片统一使用向下投影和克制的物理动效 | 提升卡片交互质感，不让界面漂浮失序 | 全部卡片复用共享 Token |
| 2026-07-25 | 红、橙、绿承担语义色，蓝色只作主操作与结构色 | 避免大面积单一蓝色 | 判断/问题/事实分色 |
| 2026-07-25 | 关联只使用细线和锚点 | 保留结构关系但不抢内容 | 选中记录到详情的低调连接 |
| 2026-07-25 | 阶段 1 视觉与交互契约冻结，进入完整本地 MVP | 用户已确认方向并明确要求实施到完成 | 不再以“原型不可写入”为边界 |
| 2026-07-25 | Tauri 2 + Rust rusqlite 是生产数据唯一所有者 | 保持离线、可审计、可迁移并减少双写 | 前端只经 `RecordRepository` 调命令，不直接执行 SQL |
| 2026-07-25 | 浏览器仓库仅作视觉和契约适配器 | 保留快速浏览器 QA，同时避免把演示数据当桌面真相 | 桌面运行必须以 SQLite 结果验收 |
| 2026-07-25 | 删除采用回收站 + 完整标题确认；版本恢复生成新版本 | 保护本地研究资料，避免覆盖历史 | 标题重输部分已被 2026-07-26 的简单确认决策取代；活动记录保护和版本恢复规则仍有效 |
| 2026-07-25 | 导入先归档原文件再解析，并用 SHA-256 识别重复 | 原始资料必须可追溯，解析失败也不能丢失输入 | 导入预览和写入都引用受控归档文件 |
| 2026-07-25 | 数据库恢复前强制生成安全备份并执行完整性检查 | 恢复属于高风险数据替换 | UI 二次确认，Rust 服务负责校验与回滚证据 |
| 2026-07-25 | Windows 正式数据默认放在 `D:\南枫情报台`，旧 AppData 仅做无损复制迁移并保留 | 用户明确指定 D 盘，同时必须防止升级迁移造成资料丢失 | `paths.rs` 统一选址；D 盘不可用或迁移失败时回退旧目录 |
| 2026-07-25 | 收藏命令只返回轻量状态，不返回整篇记录正文 | 大正文跨进程回传与重复点击会放大 WebView/IPC 稳定性风险 | UI 本地合并收藏状态，并按记录号阻止并发重复提交 |
| 2026-07-25 | 导入预览只跨 IPC 返回有上限样本，确认时由 Rust 重读归档原件 | 200 MB 文件若把全部正文往返 WebView 会造成卡顿或崩溃 | 最多展示 32 条映射样本；完整记录数、边界计数和最终写入均以后端归档原件为准 |
| 2026-07-25 | 导入日志只保存字段摘要、正文长度和 SHA-256 | 原文件、记录正文和日志三份重复正文会放大数据库体积 | `import_job_items.raw_json` 不再复制完整 `sourceText` |
| 2026-07-26 | 永久删除只保留一次明确确认，不再要求重输标题 | 记录已先进入回收站，重复输入增加操作负担但没有显著提高保护 | 活动记录仍不能永久删除；回收站确认后才执行 |
| 2026-07-26 | 原始内容日期独立存入 `records.original_at` | 导入时间不等于对话或资料发生时间 | 列表、筛选、排序、详情和导出优先使用原始日期 |
| 2026-07-26 | 附件文件操作在后台线程使用堆缓冲并原子提交 | 线程栈上的 1 MB 数组触发过 `0xc00000fd`，且同步复制会阻塞 UI | 临时文件失败即清理，数据库失败不残留新归档 |
| 2026-07-26 | Codex/Obsidian 通过 Vault/Markdown 交换层协作，不能直接写 SQLite | 保留开放整理能力，同时维持一个正式数据所有者和可追溯版本 | 导出可审阅文件，回流必须经过导入和版本机制 |
| 2026-07-26 | Markdown 展示采用 GFM + 安全清洗 + Obsidian 常用语法子集 | 需要笔记软件式阅读效果，也必须避免导入 HTML 执行风险 | 源文保持不变，展示层支持表格、任务列表、callout、wikilink 和附件 |
| 2026-07-26 | 记录选择联动使用纯亮橙色且不使用渐变；侧栏选择恢复红色 | 渐变破坏卡片质感；侧栏与内容联动需要形成明确层级，用户要求保留原有红色导航识别 | 记录边缘、关联线、锚点和详情边缘使用 `#ff681f`；侧栏选中和安全/破坏语义继续使用红色 |
| 2026-07-26 | 快速定位滑块只负责列表滚动，不隐式切换当前记录 | 拖动时连续选择会触发详情读取、连线重算和多次滚动，造成列表乱跳 | 滑块拥有独立位置状态；只有用户点击记录时才更新详情选择 |
| 2026-07-26 | 详情与完整内容共用一个 Markdown 阅读器，详情显示约一页，完整弹窗默认占窗口 85% | 两套样式会割裂，旧尺寸持久化会覆盖新默认值，过短预览和空白都降低信息密度 | 详情预览最多 2400 字符并保留 Markdown；完整内容弹窗不恢复旧尺寸但仍可手动缩放 |
| 2026-07-26 | 外部链接只交给系统默认应用，不在主 WebView 内导航 | 外站替换应用会失去明确退出路径，也会暴露第三方页面的传统滚动条和布局 | Tauri 使用 opener 权限，浏览器 QA 使用独立窗口回退；应用主工作区保持不变 |
| 2026-07-26 | 会话图片采用“引用保留 + 受控附件同名关联”，不从 UUID 推断不存在的二进制 | 现有 conversations.json 保存了引用和文件名，但正式数据目录没有对应图片文件 | 未关联时显示占位和添加入口；补充同名附件后通过受限 asset protocol 懒加载显示 |
| 2026-07-26 | 单篇记录取消平台分享按钮，提供完整 Markdown 与 DOCX 两种文件导出 | 微信、QQ、Telegram、ChatGPT 不能由当前本地应用可靠完成跨平台直达分享；复制动作也不是用户要求的真实导出 | 两种输出统一由完整记录原文组成并写入受控 exports 目录；成功提示可打开原路径 |
| 2026-07-26 | 换机备份采用可校验文件夹协议，不把日志和历史导出伪装成必要数据 | 迁移必须覆盖正式数据库、历史版本、回收站、附件、导入原件与界面偏好，同时避免备份递归和无意义体积膨胀 | `manifest.json` 声明协议版本；恢复前生成当前状态完整安全备份，失败自动尝试回滚 |
| 2026-07-26 | Windows 主窗口默认尺寸设为 1702×1066 | 与用户确认的图一信息密度和卡片比例一致 | 新启动默认使用该尺寸；不生成安装包前通过 BAT 测试版验收 |
| 2026-07-26 | ChatGPT `mapping/current_node` 会话由软件本地确定性整理 | 新导入记录不能依赖 Codex 手工修正文；原始树包含内部思考和废弃分支，直接展示会暴露无价值 JSON | 展示沿当前节点父链还原角色、日期和资源，只显示可见文本；原 JSON 保真保存，既有记录升级后自动生效 |
| 2026-07-26 | 详情卡取消重复的橙色左竖线 | 列表边框、关联线、详情边框和内容卡同时强调造成视觉噪音 | 保留列表选中与关联结构，内容区使用普通中性卡片边界 |
| 2026-07-26 | 批量导入按文件顺序执行，单项失败不终止整批 | 同时解析多个大文件会放大内存、磁盘和 WebView 压力；用户仍需要一次拖入和统一处理 | 选择器与桌面拖拽接收多路径，队列最多 100 项；每项继续走原有归档和后端重读协议，可单独映射或全部自动识别导入 |
| 2026-07-26 | Markdown callout 必须保留源类型语义，不允许统一套用单一强调色 | Obsidian 的成功、警告、危险、信息和引用表达不同含义；同色会削弱阅读层级并误导状态 | 统一阅读器负责类型别名、图标和受控语义色；普通引用保持中性，源 Markdown 不改写 |
