# 南枫知识库开发经验审计（2026-07-29）

> 本文记录 2026-07-29 的问题成因与治理经验，不再承担当前完成度入口。当前状态只以 `docs/core-workspace-acceptance-matrix.md` 和 `docs/CURRENT_HANDOFF.md` 为准。

## 最终基准

- 锁定基准：`core-workspace-design-baseline.md` 的四张核心页面；既有五套皮肤视觉合同。
- 证据：`docs/screenshots/final-core-workspace/`、`design-qa.md`、南烛枫最后确认。
- 明确排除：旧知识演化原型、旧记录页参考图、未确认探索图、仅换皮肤的页面截图。

## 反馈—原因—实现—验证矩阵

| 用户诉求 | 原问题 | 首个语义分叉/根因 | 本轮治理实现 | 当前验证 | 尚存风险 |
|---|---|---|---|---|---|
| 不能忘记四张已确认页面 | 图片只在会话临时目录 | 确认结果没有进入仓库真相源 | 复制四图、建立基线 ID/哈希和页面合同 | 最终 UI 已集成并通过自动合同/构建 | 南烛枫真实桌面完整链路尚未验收 |

## A 项目专属事实

- 三个入口及四张页面是当前最终功能组织方向。
- 知识视图默认“竞争假设”，可切换“判断演变”。
- 五套皮肤与核心页面组织是两个必须同时继承的独立合同。

## B 跨项目可复用规则

- 每张确认预览必须标注 A–F 类别、非确认类别和替代关系。
- 临时图片确认后立即进入仓库；没有受控资产和规格，不视为完成沉淀。
- 皮肤、页面布局、产品信息架构和示例内容不能互相推导。
- 任务只改一个层级时，其他已锁定层级自动进入保护范围。

## C 经授权的长期偏好

- 南烛枫明确要求：以后所有软件开发都按确认对象分类；确认后持续继承，除非南烛枫明确提出新方向。

## 被否定方案与禁止项

| 方案 | 失败原因 | 防回归资产 |
|---|---|---|
| 只在会话里记住确认图 | 会话压缩或换任务后丢失 | 受控图片目录 + 设计基线 |
| 用最新任务覆盖旧基准 | 皮肤工作替换了核心功能布局 | 修改类别/保护类别合同 |
| 后端对象存在即称核心 UI 完成 | 用户无法获得预览图中的实际阅读体验 | 分层验收矩阵 |
| 用少量样本图代表全部规则 | 容易写成截图特例 | 页面合同和对象模型共同约束 |

## 验证等级

- 已实现：通用确认合同、项目设计基线、参考资产、验收矩阵和治理入口。
- 自动测试：待本轮文档与 Skill 校验。
- 构建：本轮未改业务代码，不重复构建。
- 真实桌面：本轮未执行。
- 待验证风险：四张最终功能布局仍需正式 UI 集成和 BAT 验收。
