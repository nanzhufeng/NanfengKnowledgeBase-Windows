## 当前结论

软件已从“让用户逐条整理来源”收敛为三个知识入口：

1. `来源档案`：合并旧收录箱，统一显示已归类和待确认来源；只有例外项显示分类操作。
2. `主题结构`：合并旧主题浏览器和整理工作台；领域/主题树是主界面，新增编辑和高级结构维护默认折叠。
3. `知识视图`：以 `领域 → 主题 → 命题/竞争假设` 阅读知识成果，笔记与来源作为证据关联。

自动分类仍是默认前提。人工确认只处理低置信、冲突或没有合适主题的例外，不是日常主流程。

界面现已固定提供五套外观皮肤：`沙漠灯笼 / 花房 / 奔马 / 铜金发簪 / 原版浅色`。四套场景皮肤使用局部冷白磨砂卡片，原版浅色保留深蓝侧栏和冷灰工作区。

2026-07-29 已纠正一个重要的完成度误报：领域对象、三入口基础和五套皮肤虽然存在，但南烛枫确认的四张核心页面最终功能布局尚未完成 UI 集成，不能再把“数据模型已实现”或“皮肤已实现”表述为核心页面已经落地。

四张最终功能布局图现已进入 `docs/screenshots/final-core-workspace/`，由 `docs/core-workspace-design-baseline.md` 锁定产品组织、页面布局和交互状态；五套皮肤继续作为独立视觉合同。除非南烛枫明确提出新方向，后续开发必须同时继承二者。

### 导航与来源档案

- 顶部知识入口改为 `来源档案 / 主题结构 / 知识视图`。
- Rust 新增 `list_knowledge_source_archive`，一次读取已归类和待确认的有效来源轻量摘要。
- 来源档案支持全部/待确认/已归类筛选和标题、平台、主题搜索。
- 已归类来源显示主要主题和关联主题数，不再占用正文区展示人工分类表单。
- 待确认来源继续复用统一确定性分类、确认和撤销入口。
- 无正文空会话继续默认隐藏但不删除。

### 知识推理模型

SQLite migration v4 新增：

- 命题类型：普通命题 / 竞争假设；
- 竞争假设组；
- 命题置信度、推翻条件；
- 命题和证据的确认日、有效截止日、复核日及有效状态；
- Evidence 与 Judgment Snapshot 到 Proposition 的直接关联；
- Decision Ledger 到 Proposition / Judgment Snapshot 的关联；
- 决策已知风险、预期结果、实际行动、复核时间、结果状态、最终结果和复盘。

迁移只追加字段和索引，不修改来源正文。正式文件库首次应用 v4 前会用 SQLite online backup 自动生成一份迁移前备份，失败时事务不提交；第二次打开不会重复迁移或重复生成备份。

### 知识视图

- 命题卡展示类型、假设组、置信度、有效状态、推翻条件和复核信息。
- 命题编辑器可创建并列竞争假设，不强迫唯一结论。
- Evidence 和 Judgment Snapshot 可绑定具体命题。
- 决策账本可真实新建和编辑，并进入主题详情与本地研究上下文。
- 页面阅读顺序调整为：命题/关键转折 → 判断/证据/问题 → 决策账本 → 笔记。

### 旧规则和人工维护边界

- 旧 `catalog-rule-%` 系统规则仍由 v6 个人目录协调入口物理删除；用户自建规则不受影响。
- 主题别名、实体、规则、合并、拆分预览和关系维护保留，但统一折叠在主题结构的高级维护中。
- 没有恢复任何旧的宽泛分类规则，也没有按截图样本建立特例分支。

### 五套皮肤与磨砂玻璃

- 设置页新增固定五套皮肤选择器，选择结果仅写浏览器/WebView 的 `localStorage` 外观偏好，不写正式 SQLite。
- `沙漠灯笼`与`花房`直接使用南烛枫提供的高清原始素材；`奔马`与`铜金发簪`使用无界面、无文字、无水印的本地背景素材。
- 四套场景皮肤共用冷珍珠白玻璃层：侧栏约 87% 承托、主面板约 88% 承托，并只对卡片下方背景做 30–32 px 模糊。
- 根背景保持清晰；空白区域不套模糊，不人为扩大暗色面积。
- 不同语义卡继续保留淡绿、淡红、淡橙层次，不统一染成白卡；描边由卡片本体闭合绘制，避免伪元素裁切造成破边。
- `原版浅色`完整保留原深蓝侧栏、冷灰工作区和白卡体系。
- 皮肤唯一列表和持久化合同位于 `src/theme/knowledgeSkins.ts`，视觉复核记录位于 `design-qa.md`。
