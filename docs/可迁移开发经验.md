# 可迁移开发经验

> 基线：2026-08-14；来源是南枫知识库当前代码、测试输出、Git 历史及其项目文档。本文区分可复用原则、项目专属事实与不可直接照搬项，避免把一次产品的结论伪装为通用定律。

## 1. 通用原则

### 1.1 以链路而非页面组织改动

当一个概念跨越持久化、后端命令、服务层、界面和测试时，应从数据契约向上追踪完整链路。南枫知识库的记录/来源/主题/AI 结果均经 SQLite、Rust repository、Tauri command、TypeScript service 和工作区界面流动；只改 UI 或只改 schema 都容易留下断链。

可复用做法：先画出对象、输入、写入、读取、错误和测试责任，再做最小修改。对任何桌面、Web、移动端或自动化工具都适用。

### 1.2 分离原始事实、用户判断与 AI 派生结果

AI 应提供可审阅建议，不应静默变成事实源。可复用的模型是：保留原始输入；将 AI 输出作为带任务、版本、时间和模型信息的派生层；只有显式应用后才影响用户可见的业务状态，并允许撤销。

这条原则可降低错误生成、模型升级和供应商波动对用户资产的影响，尤其适用于知识库、账本、媒体标注和生产流程自动化。

### 1.3 把模型路由和缓存视为数据契约

模型、供应商、提示词版本、任务阶段、输入规范化规则和输出 schema 会改变结果语义。缓存不能仅以“用户问题文本相同”作为复用条件；应纳入这些稳定维度，或以版本隔离失效。

评估缓存价值至少同时看：命中率、节省 token/费用、端到端延迟、回退/失败率、同语义抽检质量，以及供应商成本数据缺口。小批真实调用能证明链路，不足以证明全量内容质量。

同样应把“凭据是否可用”和“本次任务选什么模型”拆开：凭据卡只说明一个通道能否被调用，路由策略才决定自动顺序或人工覆盖。路由在任务创建时冻结，避免设置刷新、目录变化或用户改选影响在途任务、断点和账本。

### 1.3.1 手动模型列表应是受治理目录

“供应商能返回”不等于“应出现在产品选择器”。先为每个保留模型写清业务场景、通道来源、自动/仅人工资格与回退规则；在远端目录刷新和本地历史目录读取两端执行同一过滤。历史手动选择若不再合格，应解释并安全回退自动策略，不能继续静默调用一个隐藏模型。

### 1.3.2 已保存密钥的 UI 只呈现状态，不复制秘密

界面中的圆点掩码应是视觉状态，不是把真实密钥预先送回前端再遮住。只有用户明确执行“显示”动作时，才经受控命令临时读取；替换凭据必须要求输入新值，避免把“清空输入框”误解为删除 Key。这个模式适用于系统凭据库、浏览器秘密存储和企业密钥服务。

### 1.4 将长期规则与动态状态分开

长期规则适合放在精简 `AGENTS.md`：数据安全、迁移、密钥、验证分层、发布授权。分支、端口、统计、临时失败和下一步只放动态交接。这样能减少“多个文档同时自称当前”的漂移。

可复用流程：每次文档同步先分类，再用代码、测试或 Git 记录给结论标注证据日期；发现冲突时建立登记表，而不是悄悄改写历史。

### 1.5 前向 migration、预检和最小真实验证

发布后的数据库迁移不可回写。新增 migration 应可前向执行，配合预检、备份/恢复、完整性检查和小范围真实数据验收。测试通过不能替代正式库升级；反过来也不应为验证而未经授权触碰正式数据。

这可推广到 SQLite、PostgreSQL、文件格式升级、缓存目录迁移和设备数据同步。

### 1.6 验收结论必须分层

“实现了”“单元测试通过”“编译/打包通过”“隔离应用跑通”“真实业务通过”“正式发布”是不同结论。报告需要说明命令、环境、证据日期和未覆盖边界。这样即使后续环境、浏览器端口或供应商不可用，也不会把局部成功误记为全量完成。

### 1.7 构建产物是可追踪资源，不是随手清理对象

构建缓存和验收程序可能被正在运行的应用使用。先盘点唯一共享缓存、当前验收程序、临时副本及可回滚方式；清理脚本应先 Preview，确认后才 Apply。发布则用标签、唯一安装包、SHA-256 与远端下载复验建立可追溯证据链。

## 3. 不可直接照搬的部分

1. **模型选择、温度、token、供应商和费用。** 千问 Flash/Plus/Max、DeepSeek Flash/Pro、OpenRouter Terra/Sonnet及其当前自动优先级，是南枫知识库在 2026-08-14 的项目配置，不是其他产品的默认目录；仍须按任务、账号、地区、供应商返回字段与质量标准重做评估。小批缓存证据不能变成别的项目的成本承诺。
2. **数据目录、安装器、签名与平台策略。** `D:\南枫知识库`、NSIS 和未签名安装提示属于当前 Windows 环境；macOS、移动端、企业设备或云端服务需要重新设计权限、恢复和发布流程。
3. **领域对象与 UI 皮肤。** 记录/来源/主题/洞察、五套皮肤、固定布局和内容语言是知识库的产品选择，不应复制到记账、网络守卫或媒体工具中。
4. **具体测试数量和覆盖率判断。** 213/135 只是该提交、该环境的输出；换仓库、换依赖、换测试配置后必须重新执行。
5. **历史文档中的“当前结论”。** 产品简报、性能文档和发布文档存在与当前代码/交接不一致的部分，只能作为历史线索，不能直接复用为新项目的架构事实。

## 4. 可复用的失败预防矩阵

| 反馈/风险 | 根因 | 可复用处理 | 验证方式 |
| --- | --- | --- | --- |
| 文档说法与代码不一致 | 长期文档承载动态状态 | 静态规则、动态交接、冲突登记三分 | 以当前代码和可重复命令复核 |
| AI 调用重复且成本不透明 | 无语义隔离的复用或无用量账本 | 版本化 cache key + 命中/回退/费用记录 | 契约测试和脱敏真实小批抽检 |
| AI 输出污染原始数据 | 生成结果被直接写为事实 | 派生、应用、撤销、审计分离 | 应用/撤销路径和回归测试 |
| migration 在真实库失败 | 先改正式数据、缺少预检 | 前向迁移、备份、完整性检查、小批验收 | 预检报告、恢复演练、真实库授权验收 |
| E2E 为了跑通干扰用户环境 | 端口/进程状态未知 | 先只读检查，使用隔离端口或取得确认 | 端口证据和独立测试报告 |
| 清理构建物误伤验收程序 | 不区分共享缓存与临时副本 | Preview—确认—Apply，记录 SHA 和运行路径 | 候选清单与恢复边界 |

## 5. 迁移到其他 Codex 项目的最小模板

1. 建立一个短小的长期 `AGENTS.md`，另设动态交接文档。
2. 为每个跨层业务对象写出持久化、服务、UI、失败、测试的责任图。
3. 对 AI 建立输入来源、任务记录、冻结路由、派生结果、显式应用/撤销和缓存隔离。
4. 对迁移、清理、发布和真实数据操作先写明目标、预检、回滚与授权点。
5. 将测试报告按层级输出，保留命令、日期、环境和未覆盖边界。
6. 每次大阶段结束生成一份带冲突登记的档案；不要把未执行的验证写成完成。

## 6. 本次复盘的适用边界

本次在当前工作树执行了 TypeScript、Vitest、站点辅助测试和 Rust 测试；Playwright 因 4174 端口占用未实际运行用例，未停止进程或改配置。没有重新构建安装包、操作正式数据库或进行远端发布。因此本文提供的是可复用的治理和工程经验，不构成对所有真实桌面路径、全量 AI 质量、代码签名或跨平台能力的重新认证。
