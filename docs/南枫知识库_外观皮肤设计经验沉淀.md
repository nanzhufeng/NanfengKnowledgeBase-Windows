# 南枫知识库外观皮肤设计经验沉淀

## 结论

南枫知识库已形成一套可复用的“同布局、多皮肤”外观系统：皮肤只改变背景、色彩、材质和局部对比，不改变信息架构、组件几何、功能入口和交互职责。该系统已整理为全局 Codex Skill `designing-nanzhufeng-app-skins`，并扩展出桌面、平板与手机的跨平台适配规则。

手机规则属于从桌面实现中提炼的设计标准，目前不能替代 iOS 或 Android 真机验收。

## 本次沉淀合同

### 项目与范围

- 项目：南枫知识库。
- 代码仓库：当前 `nanfeng-intelligence` 工作区。
- 允许写入：新增经验文档、全局 Skill、Mac 迁移包和已授权的长期记忆备注。
- 禁止写入：现有业务代码、正式知识库数据、用户未提交的其他改动。

### 成功标准

- 形成可触发、可验证、无项目绝对路径依赖的 Codex Skill。
- 明确桌面已实现来源与手机派生规范的证据边界。
- 提供 Mac 端可直接复制安装的完整技能目录和压缩包。
- 把统一皮肤标准写入长期记忆扩展备注。

## 用户反馈到统一规则

| 反馈类型 | 表面问题 | 根因 | 统一规则 |
| --- | --- | --- | --- |
| 不同皮肤位置割裂 | 原版浅色与玻璃皮肤布局位置不同 | 皮肤持有了独立几何 | 所有皮肤共享一个布局合同，皮肤只能覆盖表现令牌 |
| 皮肤数量失控 | 无价值皮肤增加选择成本 | 缺少目录治理 | 保留有明确差异与实际价值的皮肤，删除重复或低质量方案 |
| 背景缺乏质感 | 原图被模糊、压暗或低清放大 | 用遮罩弥补素材和承托层问题 | 原图保持清晰，只在内容区域铺浅色玻璃 |
| 主要内容被挤压 | 小字、说明和装饰元信息过多 | 没有内容优先规则 | 小字只帮助判断、定位或操作，否则删除 |
| 状态颜色混乱 | 红绿被当作装饰色 | 色彩没有语义所有权 | 橙色负责主要动作与选中，红绿只负责语义状态 |
| 切换缺乏稳定感 | 换肤同时改变尺寸或入口 | 把换肤误作页面重设计 | 换肤保持导航顺序、控件尺寸、交互与数据状态 |

## 已形成的桌面端系统

### 皮肤目录

当前代码目录包含四套皮肤：沙漠灯笼、花房、奔马和原版浅色。铜金发簪因价值不足已从目录移除，不应在后续标准中恢复。

### 共享几何

桌面端当前参考值为 12px 应用外边距、14px 主区域间距、214px 侧栏、18px 侧栏圆角和 20px 主工作区圆角。这些数字是当前产品比例，不是所有新项目必须照抄的绝对值；可复用的核心是“先锁定一套几何，再由全部皮肤共享”。

### 原版浅色

原版浅色使用深蓝导航、冷灰工作区、白色卡片、深蓝正文和橙色操作强调。它既是独立皮肤，也是没有合适背景图、设备性能不足或透明效果不可用时的可靠回退。

### 自然场景浅玻璃

场景皮肤使用清晰自然背景；侧栏、搜索、列表、详情和主工作面使用冷白半透明玻璃。空白区域继续显示背景，不对整张图做全局模糊或灰暗遮罩。卡片正文使用固定深色文字，直接落在场景上的短文字才根据局部亮度与色温自适应。

### 交互与内容密度

卡片悬浮轻微抬升，按下有克制缩放，常用反馈控制在约 100–240ms。辅助文字只在帮助判断状态、定位来源或完成操作时保留；重复标题、阅读说明、职责复述和无价值占位必须删除。

## 手机与平板派生标准

移动端共享色彩角色、表面层级、圆角关系、图标语言和状态反馈，但不复制桌面三栏：

- 平板最多同时保留两个主要面板，侧栏转为导航轨或抽屉。
- 手机使用底部导航和单列推进，筛选与轻编辑进入底部弹层。
- 触控目标、安全区、系统返回、键盘遮挡和字体缩放优先于桌面视觉复刻。
- 手机场景图使用竖屏构图；列表与正文表面提高不透明度，模糊应有低性能回退。
- 图片预览等媒体工具可以局部使用暗底，其他界面默认保持明亮高可读。

## 复用方式

新软件开始外观设计、换肤、响应式适配或视觉验收时，优先调用 `$designing-nanzhufeng-app-skins`。只需要色板候选时，可补充调用 `applying-nanzhufeng-color-style`，但完整皮肤的结构、材质、平台适配和验收仍由前者负责。

## 剩余风险

- 不同技术栈对背景模糊、窗口透明和 GPU 合成的支持不同，必须为模糊建立静态回退。
- 背景原图的授权、分辨率与竖屏裁切需要逐项目确认。
- 手机端必须在真实低配设备、系统字体放大和减少动态效果模式下复验。
