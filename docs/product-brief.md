# 产品边界

> 2026-08-12 最新用户方向：AI 自动整理是当前最高优先级。允许 OpenRouter、DeepSeek 直连与千问（阿里云百炼）直连用于主题洞察和主题管理；OpenAI/Claude 只通过 OpenRouter 使用。旧文档中的“UI 不出现模型依赖”“不扩展模型 API”等阶段限制均由本条替代，但核心离线数据、原始资料和人工确认成果仍不被模型覆盖。

## 一句话定义

南枫知识库是一套本地优先的个人知识演化系统：把来自对话、文件、字幕和研究资料的原始来源，经过可解释、可确认、可撤销的自动分类，沉淀为有层级、有关系、有时间线、可追溯证据的长期主题。

产品核心不是“存下一篇笔记”，而是回答：

- 这条资料属于哪个长期主题，为什么？
- 它与过去哪些来源、判断和问题相关？
- 当前判断发生过什么变化，证据是什么？
- 哪些内容应当合并、拆分、建立关系或继续验证？
- 下一次研究时，怎样快速取得一份可信、带来源边界的上下文？

## 当前最高产品规格

`docs/南枫知识库_产品定义与自动分类主规格.md` 是当前最高产品规格。本文只提炼边界，不能覆盖主规格中的对象、阈值、流程和验收要求。

三个核心入口的最终页面组织、功能布局和默认交互状态由 `docs/core-workspace-design-baseline.md` 锁定；五套外观皮肤属于独立视觉层。后续开发必须同时继承两类基准，不能用皮肤工作替代核心页面实现，也不能因页面重构丢失已确认皮肤。

## 当前阶段

当前进入“正式知识生产链路接入”阶段：

- 假数据原型已退出应用入口，只保留历史设计材料。
- 正式应用收敛为三个知识入口：`全部笔记`、`主题管理`、`主题洞察`；旧收录箱并入全部笔记，旧整理工作台并入主题管理。
- 辅助导航只保留`我的收藏 / 持续跟踪`；`判断更新`不再作为人工入口。新导入笔记只进入待 AI 分类状态，不再静默运行本地语义分类；主题管理生成全库分类修订，用户一次应用后写入可撤销主题关联。
- SQLite migration v3 建立独立知识对象；migration v4 增加竞争假设、事实有效期、命题证据关联和决策账本。旧 `Record` 仅作为全部笔记的内部兼容层，不定义用户可见名称。
- 新建和导入资料同步生成 `Source Item`；领域、主题和全部来源归属由 AI 修订生成，低置信与多义归属显式标记待核对，应用和撤销保留事务记录。
- 901 条活动记录已完成 migration v3 正式升级和独立只读复核；migration v4 当前只完成代码、内存库和隔离构建验证，尚未声称正式库已升级。
- 主题结构保留可撤销合并、旧路径 redirect、只读拆分预览和关系建议，但默认折叠为低频维护能力，不再构成日常主流程。
- SQLite FTS5/BM25、别名/实体规则和旧分类建议只保留搜索与历史兼容，不再生成生产分类；人工纠正继续作为 AI 归属的例外入口。
- 主题洞察以 `领域 → 主题 → 命题/竞争假设` 为阅读主轴，已接入独立 Note、Judgment Snapshot、Decision、用户确认的 Turning Point，以及带来源锚点和有效期的 Evidence。
- migration v6 已接入 AI 通道设置、动态模型目录、逐任务 Token/费用记录和单主题 AI 洞察派生表；代码与内存库已验证，正式数据库尚未打开或升级。
- AI 接入提供`OpenRouter / DeepSeek 直连 / 千问直连`。OpenRouter 动态保留 OpenAI、Claude、DeepSeek 各自最新少量大模型；千问只提供已核对的`qwen3.7-flash / qwen3.7-plus / qwen3.8-max-preview`，不依赖不受支持的通用模型枚举接口。
- AI 按任务能力固定路由，而不是让每个阶段直接照搬设置页模型：千问为`qwen3.7-flash → qwen3.7-plus → 明确选择的 qwen3.8-max-preview`；DeepSeek 为`deepseek-v4-flash → deepseek-v4-pro → deepseek-v4-pro`；OpenRouter 仅在设置页选定的同一供应商家族内识别轻量、均衡与明确高难档。缺少相应档位时保守沿用基准，禁止自动跨通道/跨供应商回退。
- AI 结果按`供应商通道 + 实际模型 + 输入快照`保留为不可覆盖版本。设置页保存的是通道与任务路由基准，也是唯一模型配置层；主题管理和主题洞察均不显示临时模型选择。所有分类、主题整合与主题洞察任务读取设置页已保存路由，任务创建时冻结实际模型，断点续跑始终使用该快照。只有审核并应用某一分类修订才会替换正式分类。
- 同一模型且输入未变时，主题洞察补充动作直接复用既有成果；主题管理的`AI 补充新增笔记`仅处理新增或正文变化的笔记，并只重整受影响主题的整合与自动来源。新模型没有自身分类基线时必须先做一次全量生成，禁止借用其他模型的语义档案。
- 主题管理 AI 在完成领域、主题和全部笔记归属后，继续为每个主题生成唯一“主题整合”，并在整合卡内明确列出同一次修订自动关联的笔记来源；主题管理卡三与主题洞察的“主题整合”面板读取同一份已应用结果。主题洞察 AI 只负责主题综述、竞争假设、判断演变和决策与行动。本地分析、本地正文提炼和本地决策草案退出生产路径。
- 最新待审核分类草稿与当前已应用修订分开读取：草稿只用于预览，不能让现有正式归属或主题整合消失。原始笔记与已确认正式对象继续可读，AI 失败时显示等待/重试而不生成本地替代内容。
- AI 主题整理必须消费主题关联来源的可读正文，而不只是标题和元数据；上下文按来源 ID 保持可追溯，并以有界条数和长度控制 Token。正文不存在时才能提示缺少具体内容。
- 主题管理在没有已应用AI全库分类时不展示旧分类或本地兜底，卡二与卡三统一为空并提示待AI生成；生成、单主题整理和批量整理均使用持久过程反馈，完成/失败结果必须由用户确认。待验证问题、知识有效性和判断演变直接消费同一主题洞察AI成果包。
- 来源/证据边界属于按需核对的追溯元信息，不与核心判断争夺AI总览正文；默认只显示来源数量，完整ID与标题清单由用户主动展开。
- 用户可一键让AI顺序整理全部未合并主题；点击后立即看到每个主题的等待、请求、重试和结果状态。批量能力复用单主题任务和逐任务Token/费用记录，失败按主题隔离，并通过连接复用、短间隔和一次瞬时错误重试提高长批次稳定性，不引入批量参数配置或并发请求复杂度。只有全部成功才报告完成；失败结果持续显示主题名称和真实原因，由用户确认关闭，并可只重试失败主题。

## 第一用户路径

```text
导入 ChatGPT / Claude / Markdown / 字幕
→ 原件归档并提取可见内容
→ AI 逐篇理解全部有效笔记并生成全库领域/主题体系
→ AI 为全部笔记生成唯一主主题归属，低置信或多义项标记待核对
→ 主题管理 AI 按最终归属生成每个主题的主题整合及其自动关联笔记来源
→ 用户审核一个完整分类修订并一次应用，可撤销
→ 用户从主题管理或主题洞察读取同一份已应用主题整合
→ 主题洞察 AI 再生成主题综述、竞争假设、判断演变和决策与行动
→ 同一主题可并列维护多个竞争假设，不强迫唯一结论
→ 命题、证据和判断记录确认时间、有效期、复核时间及推翻条件
→ 决策账本记录当时依据、风险、行动、结果与复盘
→ 需要时才进入主题管理，维护合并、拆分预览和关系
→ 所有 AI 结论保留来源绑定；人工确认对象独立存在且不被覆盖
```

## 核心对象

| 对象 | 职责 | 不能混入 |
|---|---|---|
| Domain | 稳定的顶层领域 | 单篇来源正文 |
| Topic / Subtopic | 长期知识主题、主路径、别名和关系 | 原始文件所有权 |
| Source Item | 保真的原始来源及来源元数据 | 人工整理后的判断 |
| Note | 人工整理、分析和补充说明 | 原始来源的唯一副本 |
| Proposition | 可复用的事实、推测或主张；可作为竞争假设并列存在 | 整篇长文、被强制覆盖的唯一结论 |
| Judgment Snapshot | 某个时点的判断和置信度 | 无日期的覆盖式编辑 |
| Evidence | 支持或反驳主张的证据、来源锚点和有效期 | 无来源结论、永久有效的默认假设 |
| Open Question | 尚待确认的问题和期限 | 已确认事实 |
| Turning Point | 判断变化的关键节点 | 普通更新时间 |
| Decision | 当时依据、风险、行动、结果与复盘构成的决策账本 | 背景资料、覆盖式结论 |

## 分类原则

- 主结构使用领域 / 主题 / 子主题树，保证稳定导航和唯一主路径。
- 横向联系使用别名、相关主题、多父关系和来源关系，不复制主题。
- AI 分类优先：先生成逐篇语义档案，再生成全库领域/主题，最后按最终体系分批覆盖全部有效笔记。
- 每篇笔记必须且只能生成一个主主题归属；置信度低于 70 或存在多义性时标记待核对，不由本地阈值强行改判。
- 分类必须在来源提取和标准化之后运行，避免对原始 JSON、未抽取 PDF 或不可见内部字段作错误判断。
- AI 分类先形成版本化修订，不得直接散写正式领域/主题；应用必须事务化、可审核、可撤销，并保留原因、置信度、任务用量和费用。

## 明确不做

MVP 不做：

- 云账号、实时协作或强制同步；
- AI 聊天入口、AI Hub、RAG 工作台或必须依赖模型才能读取本地知识的路径；
- Notion / Obsidian 全功能编辑器克隆；
- 以图谱或 BI 看板作为首页；
- 自动执行低置信度拆分；
- 让 Codex、Obsidian 或第三方工具直接写应用 SQLite。

## 阶段门槛

1. 假数据原型通过：完整链路可演示，信息结构、术语和交互得到确认。
2. 领域模型通过：对象职责、主路径/关系规则和迁移方案评审完成。
3. 数据层通过：迁移、回滚、原件保真、操作日志和安全备份合同通过。
4. 分类器通过：固定验收数据集达到阈值、解释和撤销要求。
5. 真实桌面路径通过：隔离数据验证后，才能进入正式数据升级。
