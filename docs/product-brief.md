# 产品边界

## 核心用户任务

把分散在财报、研究对话、访谈和文件中的判断整理为一条可长期追踪的本地记录，并能快速区分：

- 当前判断
- 已确认事实
- 关键证据
- 待验证问题
- 下一步行动
- 历史版本

产品不是自由笔记软件，也不是 AI 套壳；核心在无模型 API、断网状态下仍应可用。

## 当前阶段

阶段 1 视觉与交互骨架已经确认。当前实施本地优先桌面 MVP：记录、标签、来源、版本、搜索、导入、导出、备份与恢复均以本机 SQLite 和受控目录为准；浏览器演示仓库仅用于界面检查。

## 第一用户路径

```text
打开全部记录
→ 搜索“资本开支”
→ 选中一条记录
→ 查看结构化详情
→ 编辑当前判断
→ 显示已保存状态
→ 追加并查看历史版本
→ 进入导入中心
→ 载入 JSON 示例
→ 确认字段映射与预计导入结果
```

## MVP 成功标准

- 1440 × 900 和 1366 × 768 下主流程可用且无页面级横向溢出。
- 卡片默认、悬停、按下、选中、折叠和展开状态遵循同一套交互规则。
- 搜索、快速定位、选择、编辑、自动保存、版本打开/删除/恢复、回收站恢复和确认永久删除在 SQLite 真实链路可操作。
- JSON、Markdown、TXT、HTML 支持多选和批量拖拽；按文件顺序归档原件并计算 SHA-256，再预览、映射、去重与写入，单项失败不阻断其余文件。
- 导入资料优先显示原始内容日期；附件归档不能阻塞 UI 或因大文件导致进程退出。
- Markdown 以安全 GFM/Obsidian 子集直接展示；内部过程内容默认折叠，但不删除源文和话题中的英文。
- 可按多种范围导出 JSON、Markdown 或 Obsidian Vault，包含可选附件、原文件和历史版本；单篇笔记可直接导出完整 Markdown 或 DOCX，并打开导出目录。
- Claude 与 ChatGPT 会话 JSON 的整理必须由软件本地完成；导入后自动还原角色、当前分支、原日期与资源引用，不依赖 Codex 或模型 API。
- Windows BAT 测试版可独立构建并在断网状态运行核心功能；安装包必须等用户完成 BAT 体验验收后再生成。

## Codex + Obsidian 工作流边界

```text
南枫情报台 SQLite（唯一正式数据）
→ 按范围导出 Vault / Markdown
→ 在 Obsidian 阅读，或交给 Codex 二次整理
→ 人工审阅文件差异
→ 需要回到软件时重新导入，并通过版本机制保留历史
```

Codex 和 Obsidian 不直接写应用数据库。这样既能获得开放文件工作流，也不会引入多方同时修改同一份正式数据的冲突。

## 话题与标签决策

- MVP 不增加独立“话题”表。导入文件中的 `topics` 与 `tags` 统一规范化为标签，供搜索、筛选和导航使用。
- 原始 `topics` 值仍完整保存在导入归档与 `sourceText`，不会因规范化丢失。
- 只有当“话题”需要层级、描述、负责人或跨记录关系，而不再只是分类词时，才升级为独立领域概念和迁移表。
