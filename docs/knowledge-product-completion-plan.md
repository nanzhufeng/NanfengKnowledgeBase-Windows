# 南枫知识库核心产品闭环实施方案

更新时间：2026-07-29

状态：`IMPLEMENTED / AWAITING DESKTOP ACCEPTANCE`

## 1. 唯一目标

在不重做三入口、四套皮肤和 migration v4 对象语义的前提下，把当前“核心页面已成型”的实现推进为一条可验收的知识生产与阅读闭环：

```text
来源资料
→ 自动分类与可解释依据
→ 领域 / 主题
→ 命题 / 竞争假设
→ 笔记 / 来源 / 支持与反对证据
→ 判断演变
→ 有效期与复核提醒
→ 决策 / 行动 / 结果 / 复盘
→ 跨时期事件与研究上下文
```

## 2. 南烛枫本轮确认的分类合同

本合同替代主规格、`product-brief.md`、`domain-rules.md` 和架构所有权表中原有的 `≥90` 自动接受阈值：

| 最高候选置信度 | 结果 | 写入行为 |
|---|---|---|
| `>65` | `auto_eligible` | 默认采用最高分主题，写入可撤销分类操作；其他候选仍保留为解释和复核证据 |
| `45–65` | `candidates` | 保留最多 5 个候选，默认突出最高分，不自动归类 |
| `<45` 或无充分直接证据 | `manual` | 来源留在例外队列，建议新建主题或人工处理 |

补充约束：

- “超过 65%”按严格大于处理；当前分类分数保留两位，`65` 本身不自动归类。
- 自动归类始终采用稳定排序后的最高候选。
- 自动或人工接受都必须保留置信度、理由、信号贡献、算法版本、操作日志和撤销入口。
- 页面不得把已经自动归类的来源再称为“等待确认”；可以显示“已自动归类，可复核/撤销”。
- 全量历史升级遵循同一阈值；不得出现新导入和历史升级两套裁决规则。

## 3. 概念所有权

| 概念 | 唯一所有者 | 公开入口 | 主要消费者 |
|---|---|---|---|
| 自动接受资格 | `src/knowledge/domain.ts` | `decideClassificationAction` | 分类器、自动整理编排、测试 |
| 分类建议与确认 | `src/services/knowledgeAutoOrganizer.ts` + Rust Repository | `autoOrganizeImportedSources` / `upgradeOutdatedInboxSuggestions` / `confirmClassification` | 导入、来源档案 |
| 核心知识读取模型 | 新增纯 TypeScript 读取模型 | 从 `KnowledgeTopicDetail` 组合，不写库 | 知识视图 |
| 跨时期事件 | 同一核心知识读取模型 | 来源、笔记、证据、问题、判断、转折、决策的统一事件投影 | 判断演变中的唯一横向时间线；日期切片仅保留为底层读取能力 |
| 知识到期状态 | 同一核心知识读取模型 | 由 `validUntil`、`reviewAt`、显式有效状态和当前日期派生 | 知识视图提醒 |
| 主题关系读取 | Rust `knowledge/repository.rs` | `getTopicDetail` 返回已确认关系 | 主题管理、知识视图关联主题 |
| 证据锚点导航 | `App` 导航状态 + `KnowledgeWorkspace` 来源阅读状态 | 结构化 `sourceItemId + locator` 导航目标 | 知识视图、来源档案 |
| 决策历史 | migration v4 `decisions` + `getTopicDetail` | 全量历史只读，更新仍走现有决策命令 | 知识视图、研究上下文 |

## 4. 入口矩阵

| 入口 / 消费者 | 当前影响 | 最终行为 | 最小验证 |
|---|---|---|---|
| 新导入自动整理 | 受影响 | `>65` 自动采用最高候选；其余进入例外 | 分类领域合同 + 编排仓库契约 |
| 历史待整理升级 | 受影响 | 与新导入使用同一阈值和确认规则 | 断点续算契约 |
| 来源档案 | 受影响 | 已归类来源仍显示采用建议的分数、理由和其他候选 | 组件契约 + 隔离浏览器 |
| 主题管理 | 小幅受影响 | 读取已确认关系和结构建议，不增加主流程表单 | 组件契约 |
| 知识视图 | 主要受影响 | 展示命题下证据，并在同一阅读区展示真实笔记、来源、跨期事件、到期风险和全部决策历史 | 读取模型测试 + 组件契约 + 同视口 |
| 原始来源正文 | 精确保真 | 不改写、不回填、不截断存储 | 既有 Repository 合同 |
| migration v4 | 保护 | 不修改既有表和字段语义；只扩展读取组合 | Rust 定向测试 |
| 正式 `D:\南枫知识库` | 不在范围 | 不后台打开、写入、迁移或重建 | BAT 只生成和 `--verify` |

## 5. 分阶段实施

### 阶段 1：自动分类合同闭环

实现状态：`已实现；领域/服务合同通过`

1. 把自动资格阈值改为严格 `>65`。
2. 自动整理只确认 `auto_eligible`，并稳定采用最高候选。
3. 历史升级与新导入使用同一公开判定。
4. 来源档案读取已接受建议，持续显示置信度、理由和评分明细。
5. 更新领域规则、所有权表和分类测试。

停止条件：阈值边界、最高候选、理由保留、候选不自动写入和撤销契约通过。

### 阶段 2：知识成果层次阅读

实现状态：`已实现；正式 Repository 读取模型与隔离组件通过`

1. 新增统一知识读取模型。
2. 在知识视图中明确呈现：
   - 领域与主题路径；
   - 命题 / 竞争假设；
   - 对应支持、反对和背景证据；
   - 主题真实笔记的标题、摘要、正文和来源关系；
   - 主题真实来源及原始时间。
3. 笔记和来源成为阅读内容，不再只是数量。
4. 维护入口继续为次级操作，不恢复 CRUD 首屏。

停止条件：正式 `KnowledgeTopicDetail` 的笔记与来源均可在核心阅读区查看，空状态不使用静态数据。

### 阶段 3：跨时期事件投影与知识过期

实现状态：`已实现；固定日期领域合同与隔离组件通过`

1. 将来源进入、笔记、证据、证据失效、问题解决、判断、转折、决策和结果投影为统一事件。
2. 底部时间线支持事件类型筛选和横向滚动。
3. 支持选择日期查看当时已存在的知识状态，不写回历史。
4. 根据当前日期派生：
   - 已到复核日；
   - 已超过有效期；
   - 显式可能过时 / 已失效；
   - 当前判断依赖的过期证据。
5. 软件只提醒，不联网、不自动把事实判为错误。

停止条件：固定日期测试可重复；底层日期过滤不返回未来对象；知识视图首屏不恢复独立“时间切片”控件；过期风险有结构化原因。

### 阶段 4：证据锚点与决策闭环

实现状态：`已实现；Markdown 标题锚点、不可精确定位提示和全量决策历史隔离链路通过`

1. 点击知识视图证据跳转到来源档案并选中对应来源。
2. 在可确定的来源类型中定位消息、标题、引用或片段；PDF 页码、音视频时间码等先打开来源并突出定位标签，不伪造文件内部跳转。
3. 决策区展示全部历史版本，不再只展示最新一条。
4. 每条决策独立展示关联判断、已知风险、预期、行动、结果和复盘。
5. 增加基础复盘摘要：已完成、成功、失败、混合、待复核数量；不冒充统计校准系统。

停止条件：锚点导航保持来源选择和定位提示；历史决策不被最新版本覆盖。

### 阶段 5：验证、文档与可见验收入口

实现状态：`自动验证与隔离 BAT 已完成；南烛枫真实桌面尚未验收`

按风险执行：

1. 分类和知识读取模型领域合同；
2. Repository / Rust 定向合同；
3. TypeScript；
4. Vite；
5. Windows Tauri `--no-bundle`；
6. 同视口检查三个入口、两个知识状态、独立滚动、横向事件线和四套皮肤；
7. 生成新的隔离 BAT，仅执行 `--verify`，不由 Codex 打开正式数据。

最终报告必须区分：

- 设计与产品合同已锁定；
- 代码已实现；
- 定向合同通过；
- 构建通过；
- 隔离浏览器通过；
- BAT 已生成但未由南烛枫验收；
- 正式 migration v4 与真实桌面仍未验证。

## 6. 禁止项

- 不切回 `main`，不清理、覆盖、暂存或丢弃当前未提交成果。
- 不重做四套皮肤、左侧导航或四张核心页面的模块合同。
- 不把隔离夹具、旧原型或静态示例写入生产组件。
- 不修改、删除、重建或后台打开正式 SQLite 和正式来源正文。
- 模型 API 只允许当前已确认的 OpenRouter / DeepSeek 单主题整理闭环；不扩展更多供应商、AI Hub、RAG、云同步、安装包或发布。
- 不以构建通过替代完整产品链路验收。
