# AI 语义整理流水线

更新：2026-08-11

## 结论

领域、主题、笔记归属和主题洞察的语义内容统一由 AI 生成。生产界面不再调用本地关键词分类、正文摘要、竞争假设、判断演变或决策草案生成器。

本地代码只保留不能交给模型的保真与安全职责：原始文件/JSON/正文解析、来源 ID、全文搜索、精确去重、附件、版本、事务、审计、费用统计和撤销。没有 API Key、网络或可用模型时，原始笔记仍可阅读；AI 区显示等待或失败，不生成本地替代内容。

## 千问直连任务路由

- `qwen_direct`通过阿里云百炼 OpenAI 兼容接口调用；Key 仍仅留在 Windows 凭据库。
- 全库整理的`profiles / assignments`固定使用`qwen3.7-flash`；`structure / integrations`固定使用`qwen3.7-plus`。修订主模型记录为 Plus，逐篇档案按 Flash 模型版本保存，增量任务只能复用相同 Flash 档案。
- `profiles / assignments`属于高频、强Schema、可确定性校验的批量阶段，千问请求显式使用`enable_thinking:false`；`structure / integrations / topic insight`继续使用供应商默认思考。该策略由Rust客户端按阶段唯一决定，页面和设置不得覆盖；推理模式必须进入Prompt缓存身份。正式2条来源A/B确认关闭思考后概念、候选主题、最终归属、待核对和置信度均与开启思考一致，reasoning归零；这是小批真实证据，不替代全库质量抽检。
- 单主题洞察默认使用`qwen3.7-plus`。只有用户在共享模型选择器明确选中`qwen3.8-max-preview`时才使用高难判断档；`deepseek-v4-pro`同样必须明确选择，不存在自动回退。
- 多模型全库任务在`ai_task_model_steps`按阶段保存实际模型与批次用量；不会以单一模型名掩盖费用或结果来源。

## 数据流与所有权

```text
原始笔记
→ 本地保真解析
→ AI 逐篇语义档案
→ AI 生成全库领域/主题体系
→ AI 分批给全部有效笔记分配唯一主主题
→ 主题管理 AI 按最终归属为每个主题生成“主题整合”及自动关联笔记来源
→ 保存为 taxonomy revision（待审核）
→ 用户一次应用，事务写入正式分类，可撤销
→ 主题洞察 AI 按已应用主题重新阅读归纳笔记
→ 生成主题综述及竞争假设/判断演变/决策与行动
```

- `ai_source_profiles`：逐篇语义档案缓存；正文哈希变化后应重新生成。
- `ai_source_profile_versions`：逐篇语义档案的模型版本；只允许`同一通道 + 同一模型 + 同一正文哈希`复用，禁止跨模型借用。
- `ai_taxonomy_revisions`：领域/主题方案、每个主题的 AI 主题整合、覆盖数量、状态和应用前快照。
- `ai_taxonomy_revision_assignments`：每篇笔记的主题 key、置信度、解释和待核对标记。
- `ai_taxonomy_run_checkpoints`：未完成全库分类的来源快照、已完成批次、阶段、offset和累计Token/已知费用；仅用于安全续跑，不是正式分类结果。
- `source_topics`：只有应用修订后才更新的正式归属。
- `ai_topic_insights`：主题综述及竞争假设、判断演变、决策与行动；不拥有主题整合。
- `ai_topic_insight_versions`：按模型与输入快照保存的主题洞察历史；兼容表不再是唯一结果来源。

AI 修订应用时，未被新体系复用、没有人工锁定且没有正式判断/证据/命题/决策/独立笔记的旧空主题归档；含人工成果的主题保留。修订不得改写原始正文，撤销恢复此前主主题归属和主题状态。

## 卡片职责

### 卡二：领域与主题列表

主题管理和主题洞察继续共用同一个领域→主题树。主题管理负责：

- 生成全库 AI 分类修订；
- 显示领域数、主题数、笔记覆盖数和待核对数；
- 在应用前显示完整领域—主题草稿和各主题笔记数；
- 在全部笔记归属确定后，为每个有归属笔记的主题生成一份带来源 ID 的“AI 主题整合”；来源 ID 必须完整覆盖该主题全部归属笔记，不得遗漏、重复或跨主题引用，并在主题管理卡三直接展示；
- 审核后一次应用；
- 应用后的卡二成为两页共同读取的正式列表。

### 主题管理卡三

只保留主题边界、AI 主题整合、整合自动关联的笔记来源、完整归纳笔记、每篇归属原因/置信度/待核对状态，以及重新生成、应用、人工纠正和撤销入口。不再展示关键词权重、别名命中、65 分门槛或本地排除规则。正式卡片只读取当前已应用修订；新生成的待审核草稿不能覆盖现有正式整合。

没有已应用修订时，主题管理卡二和卡三不读取旧主题或旧来源归属，也不显示`已归入当前主题`等本地兜底；所有正式内容区为空并提示`待 AI 生成全库分类`。点击生成后先显示不定进度弹窗，成功或失败后显示需人工确认的结果弹窗；成功结果仍是待审核草稿，不自动写入正式分类。

全库分类按`24条语义档案 / 40条归属 / 8个主题整合`保存检查点。中断后再次进入主题管理会显示已完成数量、累计Token和真实错误，并询问继续、放弃重来或稍后处理；继续时只请求剩余批次。继续前必须验证笔记ID和正文哈希快照一致，材料变化则拒绝复用旧结果。主题整合的正文由AI生成，来源清单由最终归属确定性绑定，不接受模型自由返回的来源ID作为真相。

模型选择器只读取所选模型的主题洞察和分类修订；未选择“应用修订”前，任何模型草稿都不会改变两个入口共享的正式分类。`AI 补充新增笔记`以该模型最新完整分类为基线，只将新增或正文哈希变化的笔记送入档案与归属步骤，再重整受影响主题的整合与来源绑定；未受影响主题与原领域树保持不变。新模型没有自身完整基线、基线已经撤销或未变化资料缺少该模型档案时，必须明确要求先全量生成，不能悄悄改为全量或本地回退。

### 主题洞察卡三

主题洞察的“主题整合”面板直接读取当前已应用 taxonomy revision 中由主题管理 AI 生成的同一份整合及同一来源清单，不再二次生成另一份内容，也不使用全部主题笔记替换 AI 修订绑定的来源。一个 `topic insight bundle` 负责：

1. 主题综述：有主题材料时必须生成；
2. 竞争假设：仅当材料支持两种以上合理解释时出现；
3. 判断演变：材料存在明确时间顺序、更新记录、前后证据差异或立场变化时生成1–4个来源绑定节点；完全没有时间或更新信号时为空；
4. 决策与行动：仅当来源明确记载决定、行动或结果时出现。

后三个条件面板和主题综述由“AI 重新整理”更新；主题整合随下一次全库分类修订审核并应用后更新。人工确认的正式命题、判断、转折和决策作为独立记录并列显示，不被上述任一 AI 任务覆盖。

证据与来源不是第五个独立知识面板，而是贯穿各结论的 `sourceItemIds` 和可回溯原文。缺乏证据的条件面板返回空数组，不用占位内容凑齐四块。

`openQuestions`同步进入竞争假设旁的待验证问题卡；每个假设的`invalidationCondition`同步进入知识有效性卡。单主题重新整理与全库分类生成都必须用持久过程弹窗和需确认结果弹窗反馈，不能只改变按钮文字或使用自动消失通知。
