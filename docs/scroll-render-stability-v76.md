# 千条笔记滚动稳定性复盘（v76）

## 真实故障与结论

南烛枫的真实 WebView2 截图证明：问题会随列表向下滚动扩大，并同时影响侧栏、来源列表与右侧阅读面。因此它不是单个卡片圆角、文本数据或详情读取失败，而是高密度列表让 WebView2 合成树持续承受不必要的重复卡片与同步滚动写入。

此前 v75 只去除了卡片的高风险悬浮合成属性。该修复没有限制“全部加载”后 889 张卡片仍同时存在于 DOM，也没有限制全局滚轮监听对每个原始滚轮事件同步写入 `scrollTop`，故不能覆盖真实故障。

## 修复规则

1. 数据数组可以包含全部已加载笔记，但实际 DOM 只渲染可视区域前后各 6 行；3,000 条数据时稳定为约 20 行，而不是 3,000 张卡片。
2. 定位条按固定行高计算真实滚动位置，首项、中间项与末项均不得越界；它仍只滚动列表，不更改当前选中笔记。
3. 鼠标已经位于列表/正文等原生滚动层时，浏览器直接负责滚动；应用不再拦截后逐事件写 `scrollTop`。
4. 鼠标停在阅读卡标题或工具栏等非滚动区域时，才按帧合并滚动增量并转交给该卡默认正文，维持既有悬浮滚动体验。
5. 不使用 `content-visibility`、逐卡 `will-change`、全量 transform 或运行时 GPU 遮罩作为修复手段。

1. 关闭其他南枫知识库窗口，双击根目录的`启动南枫知识库-千条笔记滚动稳定性验收.bat`。

## v85 条件挂载回归修复

- 真实截图中卡二稳定只显示7张卡后留空，但定位条仍为`1 / 120`。这不是数据丢失：视口尚未挂载时`viewportHeight=0`，旧范围算法会保底渲染`1行 + 6行overscan = 7行`。
