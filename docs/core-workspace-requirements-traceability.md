# 南枫知识库核心工作区需求推导与实现边界

更新时间：2026-07-29

本文只回答一件事：三个核心入口为什么存在、各自应该展示什么、哪些旧方向必须废弃，以及四张功能图与四套皮肤分别约束什么。后续实现必须先经过本文核对，不能再从旧页面局部修补反推产品。

## 1. 需求来源与优先顺序

1. `南枫知识库_产品定义与自动分类主规格.md`决定产品定位、自动化原则、核心对象和安全边界。
2. `新建 文本文档.txt`把产品进一步升级为`命题—证据—判断—决策—结果`的个人研究与决策系统，并重排差异化优先级。
3. 南烛枫的文字说明决定旧页面合并关系和三个核心入口职责。
4. 四张最终核心页面图决定页面功能布局、信息主次、模块位置和交互状态。
5. 四套皮肤参考只决定背景、磨砂、圆角、颜色和阴影，不改变前三层。

发生冲突时，不能拿参考图中的示例文字、旧入口名称或某套皮肤颜色覆盖产品定义。

## 2. 产品核心，不是旧页面换名

南枫知识库不是记录收藏器、收录箱处理器或人工分类工作台，而是：

> 将多来源资料自动整理到长期主题结构中，并持续形成可追溯的命题、证据、判断演变、决策、行动、结果和复盘。

完整对象链：

```text
来源资料
→ 自动分类与可解释依据
→ 领域
→ 主题
→ 命题
→ 竞争假设
→ 支持/反对证据与精确锚点
→ 当前判断与判断演变
→ 事实有效期与逻辑失效条件
→ 决策
→ 行动
→ 结果
→ 复盘
→ 下一次研究上下文
```

自动化是日常使用前提：

- 最高候选严格超过 65 分时自动归类并可撤销；
- 45–65 分候选、冲突、无匹配主题才进入人工例外；
- 人工操作不得占据默认首屏；
- 自动分类必须展示依据和置信度，不能黑盒化；
- 原始来源正文不可被分类、笔记或摘要覆盖。

## 3. 三个核心入口

| 入口 | 用户打开后首先看什么 | 自动化结果 | 人工边界 | 不得恢复的旧方向 |
|---|---|---|---|---|
| 来源档案 | 来源原文、自动整理结果、主题归属、关联命题、证据锚点 | 自动分类、置信度、解释、重复状态、相关主题/命题 | 只在低置信、冲突或无匹配时调整归属 | 独立收录箱、逐条确认台、大面积分类表单 |
| 主题管理 | 领域/主题树、主题边界、自动归类依据、层级与关联、别名术语、结构建议 | 相似主题、孤立主题、合并/拆分建议、分类依据 | 新建、改名、合并、拆分、关系调整均为次级维护 | 主题浏览器与整理工作台并列、表单优先、把主题页做成维护后台 |
| 知识视图 | 按领域/主题直接阅读命题、竞争假设、证据、判断、有效期和决策结果 | 汇总来源形成的知识成果、过期提醒和判断变化 | 新证据、判断和决策维护从阅读成果进入 | “建立领域与主题”首屏、记录详情页换皮、静态假数据原型 |

三个入口不是三个孤立数据库页面，而是同一条链的三个观察面：

- 来源档案回答“资料是什么、系统为什么这样归类、证据在哪里”；
- 主题管理回答“长期知识框架如何组织、边界是否健康”；
- 知识视图回答“我目前相信什么、为什么、何时改变、采取了什么行动、结果如何”。

## 4. 四张功能图的实际含义

### 4.1 来源档案图

必须保留：

- 左侧来源搜索、筛选、状态和来源列表；
- 右侧来源正文为主体；
- 正文上方展示自动整理结果、主题归属、关键词/命题匹配和置信度；
- 右侧显示关联命题和可精确回原文的证据锚点；
- “调整归属”是例外操作，不是默认工作流。

### 4.2 主题管理图

必须保留：

- 左侧领域/主题树；
- 右侧主题详情为主体；
- 主题边界、自动归类依据、父子/相关主题、命题/来源数量和别名术语；
- 结构建议独立显示；
- 合并、拆分、改名等维护入口不得压过主题阅读。

### 4.3 知识视图：竞争假设

必须保留：

- 默认状态是`竞争假设`；
- 命题下多个假设并列，不强迫一个结论；
- 每个假设展示支持/反对证据、置信度、状态、来源锚点、有效期和证伪条件；
- 待验证问题、即将复核和最新决策是辅助阅读信息；
- 底部为横向判断时间线。

### 4.4 知识视图：判断演变

必须保留：

- 与竞争假设共用同一主题和主阅读区；
- 展示置信度变化、上版/当前判断、变化原因和关联证据；
- 显示即将复核与待验证问题；
- 展示`判断→决策→行动→结果/复盘`链；
- 切换状态不能改变左侧入口、工作区宽度或滚动位置。

## 5. 独立皮肤合同

场景皮肤沿用已确认版本：

- 清晰场景背景；
- 整个核心工作区先有一层完整、半透明、冷白磨砂底；
- 在底层之上再放搜索框、树、详情和语义卡；
- 外层留白、圆角侧栏、圆角主面板和柔和阴影保留；
- 卡片仍有淡绿、淡红、淡橙等语义层级；
- 背景只在磨砂覆盖区域模糊。

`原版浅色`使用深蓝侧栏和冷灰工作区，但外层留白、圆角、栏位起点与三套场景皮肤一致。四张功能图中的深蓝不能覆盖三套场景皮肤。

## 6. 当前代码审计

| 范围 | 当前事实 | 与最终需求的差距 | 当前结论 |
|---|---|---|---|
| 三入口导航 | 已收敛为`知识视图 / 来源档案 / 主题管理`核心分组，入口顺序和状态在四套皮肤一致 | 南烛枫真实桌面尚未确认 | 代码与隔离浏览器通过 |
| 来源档案 | 来源正文、自动整理结果、已采用建议分数/理由、所在主题命题和证据锚点已组成阅读首屏；人工调整只在异常折叠入口 | PDF 页码、音视频时间码等外部格式只提供定位说明；真实桌面尚未确认 | 代码与隔离锚点链路通过 |
| 主题管理 | 主题边界、自动分类依据、层级关联、别名和结构建议为阅读首屏；CRUD 与高级治理退到次级维护 | 正式库的真实主题密度和滚动仍待桌面确认 | 代码与隔离浏览器通过 |
| 知识视图 | 已接入 Repository；竞争假设、判断演变、笔记/来源、知识过期和全量决策历史各有唯一阅读位置；跨时期事件只在判断演变中保留，底层日期切片能力不再作为首屏控件 | 正式数据可能尚无命题、判断或决策对象；真实空状态需桌面确认 | 代码、领域合同与隔离浏览器通过 |
| 自动分类 | 新导入与历史待整理统一为最高候选严格`>65`自动采用，`45–65`保留候选，`<45`人工；理由、算法版本和撤销仍保留 | 尚未对正式库执行本版分类结果迁移或批量验收 | 领域/服务合同通过 |
| 四套皮肤 | `沙漠灯笼 / 花房 / 奔马 / 原版浅色`为唯一目录；铜金发簪已删除；原版浅色效果保留并与场景皮肤共用外框几何 | 南烛枫真实桌面尚未确认 | 四套隔离切换待本轮复验 |

因此当前可以确认“设计锁定、代码实现、自动测试/构建和隔离浏览器通过”；仍不能把这些层级说成“正式数据迁移或南烛枫真实桌面完整用户链路已通过”。

## 7. 后续落实顺序

1. 南烛枫双击新的核心产品闭环 BAT，完成真实桌面可见验收。
2. 只记录三个入口、四套皮肤、正式空状态、滚动、证据跳转和窗口宽度的真实反馈。
3. 若通过，只更新真实桌面和正式 migration v4 状态；若失败，只修复明确反馈范围。

## 8. 验收与停止条件

- 不再用导航名称、构建通过或单张截图宣布三个入口完成。
- 不使用静态假数据代替正式 Repository 集成。
- 不后台打开正式`D:\南枫知识库`。
- 不改 migration v4 已有对象语义。
- 不扩展模型 API、云同步、安装包和发布。
- 当前文档核对完成后先停在需求结论，确认实现顺序再继续页面代码。
